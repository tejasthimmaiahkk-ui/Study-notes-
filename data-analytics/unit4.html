4.1 Introduction to Business Intelligence (BI)

What is Business Intelligence?

Business Intelligence is the set of strategies, processes and technologies that collect, integrate, analyse and present business data to support better decision-making. In short: turning raw operational data into reports and dashboards that answer "how is the business doing?"
Sales dashboards for regional managers, finance MIS reports, inventory monitoring, HR attrition dashboards, hospital bed-occupancy screens, college admission dashboards.
BI process / architecture:
  1. Data sources — ERP, CRM, Excel files, databases, web, cloud apps.
  2. ETL (Extract, Transform, Load) — pull data, clean and reshape it, load it into a store. (Power Query does ETL in Power BI.)
  3. Data warehouse / data model — integrated, historical, subject-oriented data organised for analysis (star schema).
  4. Analysis — aggregation, OLAP (slice and dice, drill down), calculations (DAX measures).
  5. Presentation — reports, dashboards, alerts, mobile apps shared with decision-makers.
Mostly descriptive and diagnostic (looks at the past); quality depends on data quality; requires governance (who sees what), licences and trained users.
  • Single version of the truth across departments
  • Faster, data-driven decisions; self-service reporting
  • Spotting trends and problems early (KPIs, alerts)
  • Saves time compared to manual Excel reports
  • Improves accountability and performance tracking
  • Microsoft Power BI — most widely used, integrates with Excel/Azure
  • Tableau (Salesforce) — strong visual analytics
  • Qlik Sense — associative engine
  • Looker / Looker Studio (Google)
  • SAP BusinessObjects, Oracle Analytics, Zoho Analytics

4.2 Introduction to Power BI and its components

What is Power BI?

Power BI is Microsoft's collection of software services, apps and connectors that work together to turn unrelated data sources into coherent, visually immersive and interactive insights. Launched in 2015 (growing out of the Excel add-ins Power Query, Power Pivot, Power View and Power Map).
Companies like Adobe, Heathrow Airport and many Indian banks and IT firms use it; very common in MIS/analyst job descriptions.
Typical workflow: connect to data in Power BI Desktop → clean it in Power Query → model it → build a report → Publish to the Power BI Service → create dashboards and share → view on Power BI Mobile.
Desktop runs only on Windows; sharing in the Service needs a Pro/Premium licence and a work or school account; very large data or complex DAX requires skill to keep reports fast.

Power BI Desktop

A free Windows application — the main authoring tool. Used to connect to data, transform it (Power Query Editor), create a data model with relationships and DAX calculations, and design multi-page reports. Files are saved as .pbix.
Analysts and report developers build everything here.
Three main views: Report, Table (Data) and Model (Section 4.4).
Windows only; reports cannot be shared from Desktop itself except as files.

Power BI Service

The cloud (SaaS) platform at app.powerbi.com. Reports are published here from Desktop to be shared and consumed in a browser.
Sharing with colleagues, building dashboards by pinning visuals, scheduling data refresh, setting data alerts, creating apps for many users, collaboration in workspaces, integration with Teams/SharePoint.
Contents of a workspace: semantic models (datasets), reports, dashboards, dataflows. An on-premises data gateway lets the cloud refresh data kept on local servers.
Sharing needs Pro or Premium licences; limited report editing compared with Desktop.

Power BI Mobile

Native apps for Android, iOS and Windows to view reports and dashboards on phones/tablets.
A regional manager checks sales on the go, gets push notifications from data alerts, annotates and shares a snapshot with the team.
Report designers can create a dedicated mobile layout in Desktop (View → Mobile layout).
Viewing and light interaction only — no report building.

Power Query (data preparation, M language) · Power Pivot (in-memory data model, DAX language) · Power BI Report Server (on-premises hosting) · Power BI Embedded (show reports inside your own app) · Gateway · Power BI Report Builder (paginated, print-ready reports). Licences: Free, Pro, Premium Per User, Premium/Fabric capacity. Since 2023 Power BI is part of Microsoft Fabric.

4.3 Installing Power BI Desktop

Installation steps

Power BI Desktop is free. Two ways to install: from the Microsoft Store (recommended — updates automatically every month) or as an .exe installer from the Microsoft Download Center / powerbi.microsoft.com.
Required before any practical work in this unit.

Requirements: Windows 10 or 11 (64-bit recommended), at least 2 GB RAM (4 GB+ recommended), display 1440 × 900 or higher, .NET Framework 4.6.2+, Microsoft Edge WebView2.

  1. Open Microsoft Store → search "Power BI Desktop" → Get / Install. Or go to powerbi.microsoft.com → Products → Desktop → Download free → choose language → download PBIDesktopSetup_x64.exe.
  2. Run the installer → Next → accept the licence agreement → choose install location → Install → Finish.
  3. Launch Power BI Desktop. A welcome/start screen appears (recent files, Get data, samples).
  4. Optionally Sign in (top-right) with a work or school Microsoft account — needed to publish to the Service. (Personal Gmail/Outlook.com accounts are not accepted for the Service.)
Not available for macOS/Linux (use a Windows VM or the Service in a browser); company PCs may need admin rights.

Connection (storage) modes

Import: a copy of the data is loaded into Power BI's compressed in-memory engine (fastest, full features, needs refresh). DirectQuery: data stays in the source; every visual sends a live query (always current, slower, some limits). Live connection: connect to an existing Analysis Services model or Power BI semantic model.
Import for Excel files and most databases; DirectQuery for huge or real-time databases.
Chosen in the connection dialog (e.g. SQL Server: "Data connectivity mode").
Import has size limits (1 GB per model in Pro); DirectQuery limits Power Query transformations and DAX functions.

4.6 Data loading and transformation with Power Query

Understanding the Power Query Editor

Power Query is Power BI's ETL engine. Every cleaning action you click is recorded as a step written in the M language; when data refreshes, the steps are replayed automatically — so you clean once and reuse forever. Open it with Home → Transform data.
Removing junk rows from exported reports, fixing data types, combining monthly files, joining customer details to orders, splitting "City, State" columns.
Layout of the editor:
  • Ribbon — Home, Transform, Add Column, View, Tools, Help tabs.
  • Queries pane (left) — every table/query loaded.
  • Data preview (centre) — the table after the selected step; column headers show the data-type icon (ABC text, 123 whole number, 1.2 decimal, calendar for date…).
  • Formula bar — the M code of the selected step (turn on with View → Formula bar).
  • Query Settings (right) — Properties (query name) and Applied Steps: click any step to see the data at that point; delete or reorder steps; the gear icon edits a step.
  • Data profiling — View → Column quality (valid/error/empty %), Column distribution, Column profile.
Finish with Home → Close & Apply to load the cleaned data into the model.
Steps run in order — deleting an early step can break later ones; very complex transformations can slow refresh.

Loading data from various sources

  1. Home → Get data → Excel workbook
  2. Browse to the .xlsx file → Open
  3. Navigator: tick the sheets/tables (preview on right)
  4. Load (as is) or Transform Data (open Power Query)
  1. Home → Get data → Web
  2. Enter the URL (Basic) — e.g. a Wikipedia page with tables
  3. Choose access (Anonymous for public pages)
  4. Navigator lists the HTML tables found → select → Transform Data
  1. Home → Get data → SQL Server

Merge and append queries

Merge queries (joins)

Merge combines two tables side by side using a matching column (key), like SQL JOIN or Excel VLOOKUP. It adds columns.
Add customer name and city (Customers table) to each order (Orders table) using CustomerID.
  1. Select the main query (Orders) → Home → Combine → Merge Queries (or Merge Queries as New to create a third query).
  2. Choose the second table (Customers); click the matching column in both tables (CustomerID ↔ ID).
  3. Choose the Join Kind → OK.
  4. A new column of nested tables appears — click its expand icon and tick the columns to bring in (Name, City).
Join kindRows kept
Left outer (default)All rows from the first table, matching rows from the second
Right outerAll rows from the second, matching from the first
Full outerAll rows from both
InnerOnly rows that match in both
Left antiRows only in the first (no match) — e.g. orders with unknown customer
Right antiRows only in the second — e.g. customers who never ordered
Keys must have the same data type and clean values (trailing spaces cause mismatches); duplicates in the lookup table multiply rows.

Append queries (union)

Append stacks tables one below another — it adds rows. Columns are matched by name; a column missing in one table is filled with null.
Combine January, February and March sales files with the same structure into one table; combine sales from two branches.
Home → Combine → Append Queries (or as New) → Two tables or Three or more tables → select tables → OK. (For a whole folder of files use Get data → Folder → Combine.)
Mismatched column names ("Amount" vs "Amt") create separate columns full of nulls — rename first.

Data types and formatting

Data types in Power Query and the model

Each column has one data type, which decides what operations are possible: Text, Whole number, Decimal number, Fixed decimal number (currency, 4 decimal places), Percentage, Date, Time, Date/Time, Date/Time/Timezone, Duration, True/False, Binary.
Dates must be Date type for time intelligence and date slicers; numbers must be numeric to be summed.
Set in Power Query (header icon or Transform → Data Type; Detect Data Type guesses). After loading, in Table view or Report view use the Column tools ribbon: Format (currency ₹, percentage, thousands separator, decimal places, date format), Data category (City, Country, Postal code, Web URL, Image URL — helps maps), Summarization (Sum, Average, Count, Don't summarize — e.g. Year should not be summed), Sort by column (sort month names by month number).
Type conversion errors appear as "Error" cells (check Column quality); locale differences (dd/mm vs mm/dd) need "Using Locale" when changing type.

Model view: connect a fact table (Sales) to dimension tables (Date, Product, Customer) — a star schema. Relationships have cardinality (one-to-many usually) and a filter direction. DAX (Data Analysis Expressions) creates measures (calculated on the fly, e.g. Total Sales = SUM(Sales[Amount]), Margin % = DIVIDE([Profit], [Total Sales])) and calculated columns (computed per row and stored). CALCULATE([Total Sales], Region[Name] = "South") changes filter context. Measures are preferred for aggregations.

4.7 Visualizations and dashboards

Creating a visual

A visual (visualisation) is a chart, table, map or card on the report canvas, built from fields.
Every report page is a collection of visuals that tell one story.
  1. In Report view click an empty area of the canvas.
  2. Choose a visual type in the Visualizations pane (or just tick a field — Power BI picks a default).
  3. Drag fields into the wells: X-axis/Axis (categories), Y-axis/Values (numbers), Legend (series), Tooltips.
  4. Resize and position; format with the paintbrush (Format visual).
  5. Change the visual type anytime by clicking another icon.
Too many visuals per page confuse readers and slow the report — aim for 4–8 well-chosen visuals.

Report vs dashboard

A report is a multi-page, fully interactive document created in Desktop (or the Service) from one semantic model. A dashboard is a single-page canvas in the Power BI Service made by pinning tiles (visuals) from one or more reports — a one-screen summary for monitoring.
Analysts explore in reports; executives monitor dashboards and receive alerts.
Pin a visual: in the Service, open the report → hover the visual → pin icon → choose an existing or new dashboard. Clicking a tile opens the underlying report.
Dashboards have no slicers/filters pane and limited interactivity; only available in the Service.

Steps to create an interactive dashboard (end-to-end)

  1. Get data — Home → Get data → choose source → Transform Data.
  2. Clean in Power Query (remove, rename, types, merge/append) → Close & Apply.
  3. Model — check relationships in Model view; create measures (Total Sales, Profit %).
  4. Build visuals — cards for KPIs on top, trend line, category bar chart, map, detail table.
  5. Add interactivity — slicers, cross-filtering, drill-down hierarchy, drill-through page, tooltips, bookmarks and buttons.
  6. Format — theme (View → Themes), titles, data labels, consistent colours, alignment.
  7. Publish — Home → Publish → choose workspace; then in the Service pin visuals to a dashboard, set refresh and share.

4.8 Formatting, tooltips, slicers, filters, drill-through and bookmarks

Formatting visuals

Select a visual → Format visual (paintbrush) in the Visualizations pane. Two groups: Visual (X/Y axis, legend, data labels, colours, gridlines, markers) and General (title, effects: background, border, shadow; header icons; tooltips; alt text for accessibility).
Readable, branded, consistent reports.
Conditional formatting: colours by rules or by a field value (e.g. red for negative profit) — Format → Columns/Data colours → fx. Themes: View → Themes for a uniform colour palette. Format painter (Home) copies formatting between visuals.
Overdecorating (3D effects, many colours) hides the message.

Tooltips

A tooltip is the small pop-up shown when hovering over a data point. By default it shows the axis value and measure; you can add more fields or design a whole report-page tooltip.
Show profit and units sold when hovering over a sales bar; show a mini trend chart for each region.
Field tooltips: drag extra fields into the visual's Tooltips well. Report page tooltip: add a new page → Format page → Page information → Allow use as tooltip → Canvas settings type Tooltip (small size) → design visuals → on the main visual: Format → General → Tooltips → Type: Report page → Page: (your page).
Not available on touch devices in the same way; too much information in a tooltip clutters.

Slicers and filters

A slicer is a visual on the canvas that lets viewers filter other visuals (Region, Year, Category). Filters in the Filters pane do the same but can be hidden/locked by the author and work at three levels:
  • Visual-level — one visual only;
  • Page-level — all visuals on the page;
  • Report-level (all pages) — everything.
Filter types: Basic (tick values), Advanced (conditions like "contains", "greater than"), Top N (top 5 products by sales), Relative date (last 30 days).
A regional manager selects "South" and every visual updates.
Add a slicer: Visualizations → Slicer icon → drag a field into Field → Format → Slicer settings → Style: Vertical list, Tile (buttons), Dropdown; for numbers/dates: Between, Before/After, Relative date; Selection: single/multi select, "Select all". Sync slicers across pages: View → Sync slicers. Edit interactions (Format → Edit interactions) decides whether a slicer or visual filters, highlights or does nothing to each other visual.
Many slicers slow a report and confuse users; slicers on high-cardinality fields (customer names) are impractical — use search or Top N.

Cross-filtering and drill-down

Clicking a bar or slice in one visual cross-filters (or cross-highlights) the other visuals on the page. Visuals with a hierarchy on the axis (Year → Quarter → Month, or Category → Sub-category) support drill-down (go one level deeper) and drill-up, using the arrow icons on the visual header.
Click "Electronics" in the category chart to see only electronics sales by month; drill from 2024 into its quarters.
Turn on drill mode with the ↓ (drill down) icon, then click a data point; "Expand all down one level" (double arrow) shows the next level for all.
Hierarchies must be built (Date hierarchy is automatic for Date fields).

Drill through

Drill through lets a user right-click a data point on a summary page and jump to a separate detail page automatically filtered to that item (e.g. a product or customer).
From a "Sales by Product" chart, drill through to a "Product Details" page showing that product's monthly sales, top customers and returns.
  1. Create a new page (e.g. "Product Details") and build detail visuals on it.
  2. On that page, in the Visualizations pane (Build), drag the field (Product) into the Drill through well. Optionally set Keep all filters and Cross-report.
  3. Power BI automatically adds a Back button (top-left) to return to the source page.
  4. On any other page, right-click a data point for that field → Drill through → Product Details.
The user must discover the right-click option — add a button or text hint; the field must exist on both pages.

Bookmarks

A bookmark captures the current state of a report page — filters and slicer selections, sort order, drill location, which visuals are visible (Selection pane), spotlight/focus mode — so it can be restored with one click.
Saved views ("South region 2024"), storytelling/presentation (View → Slideshow through bookmarks), toggling between a chart and a table using buttons, "Reset filters" buttons, show/hide information panels.
  1. Set the page the way you want (filters, visibility).
  2. View → Bookmarks → Add; rename it (… → Rename). Use … → Update after changes.
  3. Choose what it stores: Data (filters/slicers), Display (visibility, spotlight), Current page; All visuals or Selected visuals.
  4. Make it clickable: Insert → Buttons → choose a button → Format → Action: On → Type: Bookmark → Bookmark: (name). Or Insert → Buttons → Navigator → Bookmark navigator for automatic buttons.
  5. In Desktop, Ctrl + click a button to test it.
Bookmarks don't update automatically when the report changes — you must Update them; personal bookmarks in the Service are separate from report bookmarks.
