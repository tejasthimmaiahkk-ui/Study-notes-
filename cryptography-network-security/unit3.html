3.1 Modern block ciphers: modes of operation

DES and AES encrypt exactly one block (64 or 128 bits). Real messages are longer. A mode of operation is the rule for applying a block cipher to a sequence of blocks P₁, P₂, …, PN. NIST defines five classic modes. (Notation: E = encryption with key K, D = decryption, ⊕ = XOR, IV = initialisation vector — a non-secret starting block.)

Electronic Codebook (ECB)

Each block is encrypted independently with the same key: Ci = EK(Pi), Pi = DK(Ci). Like a codebook: the same plaintext block always gives the same ciphertext block.
Only for encrypting single short values such as one key or one block of random data.
Blocks can be encrypted in parallel; an error in one ciphertext block affects only that block. Needs padding.
Patterns leak — identical plaintext blocks give identical ciphertext blocks (see the "ECB penguin" demo below). Blocks can be reordered, deleted or replayed without detection. Never use ECB for messages.

Cipher Block Chaining (CBC)

Each plaintext block is XORed with the previous ciphertext block before encryption: Ci = EK(Pi ⊕ Ci−1),   C₀ = IV      Pi = DK(Ci) ⊕ Ci−1
Most common mode for many years: TLS 1.0–1.2, IPSec ESP, file encryption.
Identical plaintext blocks now give different ciphertext. The IV must be unpredictable (random). Decryption can be parallel; encryption cannot.
Sequential encryption (slower); an error in Ci corrupts Pi fully and one bit of Pi+1; padding-oracle attacks if implemented carelessly.

Cipher Feedback (CFB)

Turns a block cipher into a self-synchronising stream cipher. A shift register (initially IV) is encrypted; the leftmost s bits of the result are XORed with s bits of plaintext; the ciphertext bits are fed back into the register. Ci = Pi ⊕ MSBs(EK(Si−1))
Character-oriented transmission (s = 8 bits), e.g. terminal sessions, where data units are smaller than a block.
Only the encryption function of the block cipher is used, even for decryption. No padding needed.
Slow when s is small (one block encryption per s bits); errors propagate for a few units.

Output Feedback (OFB)

Like CFB but the output of the encryption (not the ciphertext) is fed back. This produces a key stream independent of the plaintext — a synchronous stream cipher. Oi = EK(Oi−1), O₀ = IV     Ci = Pi ⊕ Oi
Noisy channels (satellite) — a bit error in transmission affects only that bit.
Key stream can be precomputed before the message arrives.
The IV must never repeat with the same key (key-stream reuse = one-time-pad reuse); bit-flipping attacks are easy.

Counter (CTR)

Encrypt a counter value for each block and XOR it with the plaintext: Ci = Pi ⊕ EK(Counter + i)
Modern standard choice: AES-CTR and its authenticated version AES-GCM are used in TLS 1.3, IPSec, SSH, disk encryption.
Fully parallel for encryption and decryption; random access to any block; precomputation possible; no padding.
The counter/nonce must never repeat under the same key. Provides no integrity on its own (GCM adds it).

3.2 Modern stream ciphers

A modern stream cipher generates a pseudo-random key stream of bits from a short key and XORs it with the data. They are classified by how the key stream is produced.

Key stream is independent of plaintext and ciphertext (OTP, LFSR-based, RC4, OFB, CTR). Sender and receiver must stay in step; a lost bit desynchronises them, but a flipped bit affects only one bit.

Each key-stream bit depends on previous ciphertext bits (CFB mode). After an error, the receiver automatically resynchronises after a few units.

Feedback shift registers (FSR) and LFSR

A shift register of m cells (bits bm−1 … b₀). Each clock tick, the rightmost bit b₀ is output, all bits shift right, and a new leftmost bit is computed by a feedback function of the current cells. In a Linear FSR the feedback is an XOR of selected cells ("taps"), described by a feedback polynomial.
Key-stream generators in hardware: GSM's A5/1 (three LFSRs), Bluetooth E0, CRC checksums, pseudo-random test patterns.
Example: 4-bit LFSR with b₄ = b₁ ⊕ b₀ (polynomial x4 + x + 1), seed 0001. A well-chosen ("primitive") polynomial gives the maximum period 2m − 1 = 15 bits before repeating. Try it in the demo.
LFSRs are linear: from 2m output bits an attacker can recover the whole register with the Berlekamp–Massey algorithm. They must be combined non-linearly (irregular clocking, non-linear filters).

RC4

Designed by Ron Rivest (1987). A byte-oriented stream cipher with a variable key of 1–256 bytes. Its state is a permutation S of the 256 byte values plus two indices i, j.
Once the most widely used stream cipher: SSL/TLS, WEP and WPA-TKIP Wi-Fi, Microsoft Office/PDF encryption.

1. Key scheduling (KSA): S = [0, 1, …, 255]; T = key repeated to 256 bytes. For i = 0 … 255: j = (j + S[i] + T[i]) mod 256; swap S[i], S[j].

2. Key-stream generation (PRGA): repeat: i = (i + 1) mod 256; j = (j + S[i]) mod 256; swap S[i], S[j]; output k = S[(S[i] + S[j]) mod 256].

3. C = P ⊕ k (byte by byte). Test: key "Key", plaintext "Plaintext" → BB F3 16 E8 D9 40 AF 0A D3.

Biases in the first key-stream bytes; the WEP attack (2001) recovered keys because WEP put the IV next to the key. Prohibited in TLS since 2015 (RFC 7465).

A5/1 (GSM phones): three LFSRs of 19, 22 and 23 bits, clocked irregularly by a majority rule; 64-bit key. Broken in real time with precomputed tables. ChaCha20 (Bernstein, 2008) uses only additions, rotations and XORs on 32-bit words (ARX) and is the modern replacement for RC4 in TLS 1.3 and WhatsApp.

3.3 Prime numbers, Euler's φ, Fermat and Euler theorems

Public-key cryptography is built on facts about primes. You need from Unit I: divisibility, gcd, ℤn*, modular exponentiation. Everything else is developed here.

Primes and their cardinality

A positive integer p > 1 is prime if its only divisors are 1 and p (2, 3, 5, 7, 11, …). Otherwise it is composite. 1 is neither. Two numbers are coprime if gcd = 1.
There are infinitely many primes (Euclid's proof): suppose p₁, …, pn were all of them; then N = p₁p₂…pn + 1 leaves remainder 1 when divided by every pi, so N has a prime factor not in the list — contradiction.
How many? The number of primes ≤ n, π(n), is roughly n / ln n (Prime Number Theorem). Around 21024, about 1 in 710 numbers is prime — so large primes are plentiful.
RSA needs two random 1024-bit primes; Diffie–Hellman, ElGamal and DSA need a large prime modulus.
Checking for primeness (trial division): n is prime if no prime ≤ √n divides it. Is 97 prime? √97 ≈ 9.8; 97 is not divisible by 2, 3, 5 or 7 → prime. Sieve of Eratosthenes lists all primes up to n by crossing out multiples.
Trial division needs about √n steps — for a 300-digit n that is 10150 steps, impossible. Hence probabilistic tests (3.4).

Euler's phi (totient) function φ(n)

φ(n) = the number of integers in 1 … n−1 that are coprime to n = the size of ℤn*.
Choosing RSA keys (e·d ≡ 1 mod φ(n)); Euler's theorem; counting primitive roots.
φ(1) = 0    φ(p) = p − 1 (p prime)    φ(m × n) = φ(m) × φ(n) if gcd(m, n) = 1    φ(pe) = pe − pe−1 General: n = p₁e₁ p₂e₂ … ⇒ φ(n) = n (1 − 1/p₁)(1 − 1/p₂) …
Examples: φ(13) = 12; φ(10) = φ(2)φ(5) = 1 × 4 = 4; φ(49) = 49 − 7 = 42; φ(240): 240 = 24 × 3 × 5 → (16 − 8)(2)(4) = 64. For RSA: φ(p × q) = (p − 1)(q − 1).
Computing φ(n) requires the factorisation of n. Knowing φ(n) for n = pq is equivalent to factoring n — this is exactly why RSA is secure.

Fermat's little theorem

If p is prime and a is not a multiple of p: ap−1 ≡ 1 (mod p)      (second form, any a: ap ≡ a (mod p))
(1) Fast exponentiation by reducing exponents mod p − 1; (2) multiplicative inverse without Euclid: a−1 ≡ ap−2 (mod p); (3) the Fermat primality test; (4) proof of RSA.
610 mod 11 = 1 (directly). 312 mod 11: 312 = 310 × 32 ≡ 1 × 9 = 9. Inverse of 8 mod 17: 815 mod 17 = 15 (check 8 × 15 = 120 = 7 × 17 + 1 ✓).
The converse is false: some composites (Carmichael numbers, e.g. 561) satisfy an−1 ≡ 1 for all coprime a.

Euler's theorem

Generalises Fermat to any modulus n: if gcd(a, n) = 1, aφ(n) ≡ 1 (mod n) A useful variant for RSA: if n = p × q and k is an integer, ak×φ(n)+1 ≡ a (mod n) for every a (even when gcd(a, n) ≠ 1).
Proves RSA decryption works; computes large powers; a−1 ≡ aφ(n)−1 (mod n).
2062 mod 77: φ(77) = φ(7)φ(11) = 6 × 10 = 60 → 2062 = 2060 × 202 ≡ 400 mod 77 = 15.
Needs φ(n), i.e. the factorisation of n.

3.4 Primality testing

To generate a 1024-bit prime we pick random odd numbers and test them until one is prime. Tests are deterministic (always correct, often slow) or probabilistic (very fast, with a tiny, controllable error probability).

Divisibility (trial-division) algorithm — deterministic

Divide n by every integer (or prime) from 2 to √n. If none divides n, n is prime.
Small numbers; first quick filter (divide by small primes) before expensive tests.
Bit-operation complexity is exponential in the number of bits: about 2b/2 divisions for a b-bit number.
Useless for cryptographic sizes.

Fermat test — probabilistic

Pick a base a. If an−1 ≢ 1 (mod n), n is definitely composite. If an−1 ≡ 1, n is probably prime.
Fast first test (e.g. PGP historically).
Is 561 prime? 2560 mod 561 = 1 → "probably prime" — but 561 = 3 × 11 × 17! Is 15 prime? 214 mod 15 = 4 ≠ 1 → composite ✓.
Fooled by Carmichael numbers (561, 1105, 1729 …) for every base coprime to n.

Square-root test

If n is prime, the only square roots of 1 mod n are ±1 (i.e. 1 and n − 1). If we find x with x2 ≡ 1 but x ≢ ±1, n is composite.
Combined with Fermat in Miller–Rabin.
mod 8: 3² = 9 ≡ 1, but 3 ≢ ±1 → 8 is composite. mod 7: only 1² and 6² give 1 → consistent with 7 prime.
On its own you must find such an x, which is hard — so it is used inside Miller–Rabin.

Miller–Rabin test — probabilistic (used in practice)

Write n − 1 = m × 2k with m odd. Choose a random base a (1 < a < n − 1). Compute T = am mod n, then square it repeatedly k − 1 times. n passes (is "probably prime") if T ≡ ±1 at the start, or T becomes n − 1 at some squaring. If T becomes 1 without passing through n − 1, or never reaches n − 1, n is composite. It combines Fermat with the square-root test.
OpenSSL, Java BigInteger.isProbablePrime, RSA key generation in every library.
  1. Find m, k: n − 1 = m·2k.
  2. T = am mod n. If T = 1 or T = n − 1 → probably prime.
  3. Repeat k − 1 times: T = T² mod n. If T = n − 1 → probably prime; if T = 1 → composite.
  4. If the loop ends without n − 1 → composite.
Example n = 561, a = 2: 560 = 35 × 24. T = 235 mod 561 = 263 (not ±1). Square: 166 → 67 → 1. We reached 1 without seeing 560 → 561 is composite (67 is a non-trivial square root of 1). Fermat was fooled; Miller–Rabin is not.
A composite passes for at most 1/4 of bases, so t random bases give error ≤ (1/4)t — with t = 40, less than 10−24. Still probabilistic.

In 2002 Agrawal, Kayal and Saxena (IIT Kanpur) proved that primality can be tested deterministically in polynomial time — a famous result. It is slower than Miller–Rabin in practice, so libraries still use probabilistic tests.

3.5 Factorization

Fundamental theorem of arithmetic

Every integer n > 1 can be written uniquely as a product of primes: n = p₁e₁ × p₂e₂ × … (e.g. 600 = 23 × 3 × 52).
GCD = product of common primes with the smallest exponents, LCM = largest exponents; φ(n) formula. RSA's security: multiplying p × q is easy, recovering p and q from n is hard — a one-way function.
gcd(600, 70): 600 = 2³·3·5², 70 = 2·5·7 → gcd = 2·5 = 10, lcm = 2³·3·5²·7 = 4200.
Finding the factorisation of large n is believed to be hard; no polynomial-time classical algorithm is known.

Trial division method

Divide n by 2, 3, 5, … up to √n, record each factor found and continue with the quotient.
Small n, or removing small factors first.
1233 → ÷3 = 411 → ÷3 = 137 → 137 prime. So 1233 = 3² × 137.
Exponential time: hopeless for a 2048-bit RSA modulus.

Fermat's factorization method

If n = p × q with p and q close together, then n = x² − y² = (x − y)(x + y) with x = (p + q)/2, y = (q − p)/2. Search x = ⌈√n⌉, ⌈√n⌉ + 1, … until x² − n is a perfect square y².
Shows why RSA primes must not be too close to each other.
n = 5959: √5959 ≈ 77.2 → start x = 78: 78² − 5959 = 125 (not a square); x = 79: 282 (no); x = 80: 6400 − 5959 = 441 = 21² ✓. So n = (80 − 21)(80 + 21) = 59 × 101.
Very slow when p and q are far apart.

Pollard p − 1 method

Works when p − 1 has only small prime factors (is "B-smooth"). Compute a = 2B! mod n step by step (a = ae mod n for e = 2 … B), then p = gcd(a − 1, n). If p − 1 divides B!, then 2B! ≡ 1 (mod p) by Fermat, so p divides a − 1.
Reason RSA primes are chosen so that p − 1 has a large prime factor ("strong primes").
n = 1403, B = 5: a = 2; a = a² = 4; a = a³ = 64; a = a⁴ mod 1403; a = a⁵ mod 1403 → a = 794. gcd(793, 1403) = 61 → 1403 = 61 × 23. (Works because 61 − 1 = 60 = 2² · 3 · 5 divides 5! = 120.)
Fails if neither p − 1 nor q − 1 is smooth; may return 1 or n and need another B.

Pollard rho (finds small factors in ~√p steps), the quadratic sieve and the general number field sieve (GNFS) — the fastest known, used to factor RSA-250 (829 bits) in 2020 with ~2700 CPU-core-years. That is why RSA keys are now ≥ 2048 bits. A large quantum computer running Shor's algorithm would factor in polynomial time — the motivation for post-quantum cryptography.

3.6 Chinese Remainder Theorem (CRT)

Statement and solution method

The CRT (Sun Tzu, ~3rd century AD) solves a system of congruences with pairwise coprime moduli: x ≡ a₁ (mod m₁),   x ≡ a₂ (mod m₂),   …,   x ≡ ak (mod mk) There is exactly one solution modulo M = m₁ × m₂ × … × mk.
Speeds up RSA decryption about 4× (compute mod p and mod q separately, then combine); Rabin decryption; secret sharing; representing big numbers as small residues for parallel arithmetic.
  1. M = m₁ × m₂ × … × mk.
  2. Mi = M / mi for each i.
  3. Mi−1 = inverse of Mi modulo mi.
  4. x = (a₁M₁M₁−1 + a₂M₂M₂−1 + … + akMkMk−1) mod M.
Moduli must be pairwise coprime (otherwise there may be no or many solutions).
  1. M = 3 × 5 × 7 = 105.
  2. M₁ = 105/3 = 35, M₂ = 105/5 = 21, M₃ = 105/7 = 15.
  3. Inverses: 35 ≡ 2 (mod 3) → 2−1 = 2; 21 ≡ 1 (mod 5) → 1; 15 ≡ 1 (mod 7) → 1.
  4. x = (2·35·2 + 3·21·1 + 2·15·1) mod 105 = (140 + 63 + 30) mod 105 = 233 mod 105 = 23.
  5. Check: 23 = 7·3 + 2 ✓, 23 = 4·5 + 3 ✓, 23 = 3·7 + 2 ✓

3.7 Quadratic congruence and discrete logarithms

The Rabin cryptosystem needs square roots modulo a prime; ElGamal and ECC need the discrete logarithm problem. These two short topics fill that gap.

Quadratic residues and square roots mod p

a is a quadratic residue (QR) mod p if x² ≡ a (mod p) has a solution. For an odd prime p, exactly (p − 1)/2 non-zero numbers are QRs, and each has two roots ±x. Euler's criterion: a is a QR ⇔ a(p−1)/2 ≡ 1 (mod p).
Rabin decryption; also used in some primality tests.
QRs mod 11 are {1, 3, 4, 5, 9} (squares of 1…10). When p ≡ 3 (mod 4), roots are easy: x ≡ ±a(p+1)/4 (mod p). e.g. x² ≡ 3 (mod 23): 36 = 729 ≡ 16 → x = ±16 = 16, 7. Check 16² = 256 = 11·23 + 3 ✓.
Square roots modulo a composite n are as hard as factoring n — the basis of Rabin's security.

Primitive roots and the discrete logarithm

The order of a in ℤn* is the smallest i with ai ≡ 1. If the order equals φ(n), a is a primitive root (generator): its powers produce every element of ℤn*. The discrete logarithm of y to base g is the exponent x with gx ≡ y (mod p).
Diffie–Hellman, ElGamal, DSA and (on curves) ECC rely on: computing gx mod p is easy, but finding x from gx is hard for large p.
In ℤ₁₁*, g = 2: 2¹…2¹⁰ ≡ 2, 4, 8, 5, 10, 9, 7, 3, 6, 1 — all 10 elements, so 2 is a primitive root. Discrete log: log₂ 9 = 6 (because 26 = 64 ≡ 9).
For small p a table solves it instantly; security needs p of 2048+ bits (or an elliptic curve of 256 bits).

3.8 Asymmetric-key cryptography: the idea

Public and private keys

Proposed by Diffie and Hellman (1976). Each user (Bob) creates a key pair: a public key published to the world and a private key he alone keeps. Alice encrypts with Bob's public key; only Bob's private key decrypts. Think of a padlock: anyone can snap it shut (public key), only the key-holder can open it (private key).
Solves the key-distribution problem of symmetric crypto: n users need only n key pairs instead of n(n − 1)/2 secret keys. Enables digital signatures (Unit IV).
Built on a trapdoor one-way function: y = f(x) is easy to compute, x = f−1(y) is infeasible — unless you know a secret "trapdoor". RSA: f(x) = xe mod n, trapdoor = factors p, q. ElGamal: f(x) = gx mod p (discrete log).
Much slower than symmetric ciphers (RSA ≈ 1000× slower than AES), so in practice it encrypts only a symmetric session key (hybrid encryption). Requires authenticating public keys (certificates) to prevent man-in-the-middle.

3.9 The RSA cryptosystem

RSA: key generation, encryption, decryption

Invented by Rivest, Shamir and Adleman (MIT, 1977), the most widely used public-key algorithm. Plaintext and ciphertext are integers in ℤn. Security rests on the difficulty of factoring n = p × q.
TLS certificates and key exchange (older versions), digital signatures (software updates, Aadhaar e-sign, DSC for income-tax filing), PGP/S-MIME e-mail, SSH keys, smart cards.

Key generation (Bob):

  1. Choose two large distinct primes p and q.
  2. n = p × q   and   φ(n) = (p − 1)(q − 1).
  3. Choose e with 1 < e < φ(n) and gcd(e, φ(n)) = 1.
  4. Compute d = e−1 mod φ(n) (extended Euclid).
  5. Public key = (e, n); private key = d (keep p, q, φ(n) secret or destroy them).
Encryption (Alice): C = Pe mod n      Decryption (Bob): P = Cd mod n

Requirement: P < n.

Why it works: Cd = Ped, and ed = 1 + kφ(n), so Ped = Pkφ(n)+1 ≡ P (mod n) by Euler's theorem (second version).

Slow; deterministic textbook RSA is insecure (same message → same ciphertext); needs padding (OAEP). A 2048-bit key is the current minimum; quantum computers would break it.
  1. n = 17 × 11 = 187; φ(n) = 16 × 10 = 160.
  2. e = 7: gcd(7, 160) = 1 ✓.
  3. d = 7−1 mod 160. Extended Euclid: 160 = 22·7 + 6; 7 = 1·6 + 1 → t-values 0, 1, −22, 23 → d = 23. Check 7 × 23 = 161 = 160 + 1 ✓.
  4. Public key (7, 187), private key 23.
  5. Encrypt C = 887 mod 187. 882 = 7744 ≡ 77; 884 ≡ 77² = 5929 ≡ 132; 887 = 884·882·88 ≡ 132 × 77 × 88 = 894,432 ≡ 11.
  6. Decrypt P = 1123 mod 187 = 88 ✓ (use square-and-multiply: 23 = 16 + 4 + 2 + 1).

3.10 The Rabin cryptosystem

Rabin: a variant of RSA with e = 2

Proposed by Michael Rabin (1979). Encryption is squaring modulo n = p × q: C = P² mod n. Decryption needs square roots mod n, which is easy with p and q (via CRT) and provably as hard as factoring without them — something not proven for RSA.
Very fast encryption (one multiplication) — attractive for low-power devices that only encrypt (e.g. smart cards sending to a server).

Key generation: choose primes p, q with p ≡ q ≡ 3 (mod 4); public key n = pq, private key (p, q).

Encryption: C = P² mod n.

Decryption:

  1. a₁ = +C(p+1)/4 mod p,   a₂ = −C(p+1)/4 mod p
  2. b₁ = +C(q+1)/4 mod q,   b₂ = −C(q+1)/4 mod q
  3. Combine with CRT: P₁ = CRT(a₁, b₁), P₂ = CRT(a₁, b₂), P₃ = CRT(a₂, b₁), P₄ = CRT(a₂, b₂).
  4. One of the four is the plaintext (redundancy such as a fixed header identifies it).
Four possible plaintexts — the receiver must pick the right one. Vulnerable to a chosen-ciphertext attack (a decryption oracle reveals the factors).
  1. 23 ≡ 3 and 7 ≡ 3 (mod 4) ✓. n = 161.
  2. C = 24² mod 161 = 576 mod 161 = 93.
  3. a₁ = 936 mod 23 = 1 (since 93 ≡ 1 mod 23), a₂ = 23 − 1 = 22.
  4. b₁ = 932 mod 7 = 2² = 4 (since 93 ≡ 2 mod 7), b₂ = 7 − 4 = 3.
  5. CRT: (1, 4) → 116; (1, 3) → 24; (22, 4) → 137; (22, 3) → 45.
  6. Candidates 116, 24, 137, 45 — the true plaintext 24 is among them.

3.11 The ElGamal cryptosystem

ElGamal encryption

Proposed by Taher ElGamal (1985), based on the discrete logarithm problem in ℤp*. Encryption is randomised: a fresh random r is used each time, so the same plaintext gives different ciphertexts.
GnuPG/PGP encryption keys, the basis of the DSA signature standard, and (on elliptic curves) of ECC encryption.

Key generation: large prime p, primitive root e₁ of ℤp*, private d (1 ≤ d ≤ p − 2), e₂ = e₁d mod p. Public key (e₁, e₂, p); private key d.

Encryption: random r;   C₁ = e₁r mod p;   C₂ = (P × e₂r) mod p. Send (C₁, C₂).

Decryption: P = [C₂ × (C₁d)−1] mod p.

Why it works: C₁d = e₁rd = e₂r, so C₂ × (C₁d)−1 = P × e₂r × (e₂r)−1 = P.

Ciphertext is twice as long as the plaintext. Reusing r for two messages lets an attacker who knows one plaintext compute the other. p must be ≥ 2048 bits.
  1. e₂ = 2³ mod 11 = 8. Public (2, 8, 11), private 3.
  2. C₁ = 2⁴ mod 11 = 16 mod 11 = 5.
  3. C₂ = 7 × 8⁴ mod 11; 8⁴ = 4096 ≡ 4 → 7 × 4 = 28 ≡ 6. Ciphertext (5, 6).
  4. Decrypt: C₁d = 5³ = 125 ≡ 4; 4−1 mod 11 = 3; P = 6 × 3 = 18 ≡ 7 ✓.

3.12 Elliptic Curve Cryptography (ECC)

Elliptic curves over real numbers

An elliptic curve is the set of points (x, y) satisfying y² = x³ + ax + b,   with 4a³ + 27b² ≠ 0 (no cusps or self-crossings) plus a special point at infinity O. (It is not an ellipse — the name comes from elliptic integrals.) The curve is symmetric about the x-axis.
Understanding the geometry makes the formulas over finite fields meaningful.
Point addition (geometric rule):
  • P ≠ Q: draw the line through P and Q; it meets the curve at a third point R′. Reflect R′ in the x-axis: P + Q = R.
  • P = Q (doubling): use the tangent at P instead.
  • Q = −P (mirror image): the line is vertical and meets the curve "at infinity": P + (−P) = O. O acts like zero: P + O = P.
λ = (y₂ − y₁)/(x₂ − x₁)   if P ≠ Q     λ = (3x₁² + a)/(2y₁)   if P = Q x₃ = λ² − x₁ − x₂     y₃ = λ(x₁ − x₃) − y₁
Real-number curves have rounding errors — cryptography uses curves over finite fields.

Elliptic curves over GF(p)

The same equation, but all arithmetic is mod p (prime): Ep(a, b). The "curve" becomes a finite scatter of points. Division in λ means multiplying by the modular inverse. Repeated addition gives scalar multiplication k × P = P + P + … + P.
Real curves: P-256 (NIST), Curve25519 (WhatsApp, Signal, TLS 1.3, SSH), secp256k1 (Bitcoin, Ethereum).
E₂₃(1, 1): y² ≡ x³ + x + 1 (mod 23) has 27 affine points + O = 28 points.
P = (3, 10), Q = (9, 7): λ = (7 − 10)/(9 − 3) = −3 × 6−1 = −3 × 4 = −12 ≡ 11. x₃ = 121 − 3 − 9 = 109 ≡ 17; y₃ = 11(3 − 17) − 10 = −164 ≡ 20 → P + Q = (17, 20).
2P: λ = (3·9 + 1)/(2·10) = 28 × 20−1 ≡ 5 × 15 = 75 ≡ 6. x₃ = 36 − 6 = 30 ≡ 7; y₃ = 6(3 − 7) − 10 = −34 ≡ 12 → 2P = (7, 12).
Curves must be chosen carefully (avoid anomalous or small-order curves); implementation bugs (invalid-curve attacks, bad randomness — the Sony PS3 ECDSA failure) are common.

ECC cryptosystem (ElGamal on a curve) and its security

ECDLP: given points G and Q = k × G, finding k is infeasible for large curves. This is the trapdoor.
Same security as RSA with much smaller keys → faster, less bandwidth, less power: ideal for mobiles, smart cards, IoT.

Keys: curve Ep(a, b), generator point e₁; private d; public e₂ = d × e₁.

Encrypt (plaintext encoded as a point Pm): random r; C₁ = r × e₁; C₂ = Pm + r × e₂.

Decrypt: Pm = C₂ − d × C₁ (because d × C₁ = d·r·e₁ = r × e₂).

ECDH key exchange: Alice sends a·G, Bob sends b·G; both compute the shared point a·b·G.

3.13 Hash functions

Cryptographic hash function

A function h that maps a message of any length to a fixed-length digest (fingerprint), e.g. 512 bits for SHA-512. The digest is used to check integrity: if even one bit of the message changes, the digest changes completely (avalanche).
File/download verification, password storage (with salt), digital signatures (sign the digest), MACs, blockchain proof-of-work, Git commit IDs, deduplication.
Three security properties (learn these exactly):
  1. Preimage resistance (one-way): given a digest d, it is infeasible to find any M with h(M) = d.
  2. Second-preimage resistance (weak collision resistance): given M, infeasible to find M′ ≠ M with h(M′) = h(M).
  3. Collision resistance (strong): infeasible to find any pair M ≠ M′ with h(M) = h(M′).
Also: computing h(M) must be efficient, and the output must look random.
A plain hash proves integrity only if the digest itself is protected; an attacker who changes the message can recompute an unkeyed hash. Collisions must exist (infinitely many inputs, finitely many outputs) — the goal is that nobody can find one.

The birthday problem — why digests must be long

In a room of only 23 people, the chance that two share a birthday exceeds 50 %. Similarly, for an n-bit hash an attacker expects to find a collision after only about 2n/2 random messages (not 2n).
Determines digest length: a 128-bit hash (MD5) gives only 264 collision security; SHA-512 gives 2256.
P(no match among k people) = 365/365 × 364/365 × … × (365 − k + 1)/365. For k = 23: P(match) ≈ 0.507.
Applies to collision resistance; preimage attacks still cost 2n.

Iterated hash: the Merkle–Damgård construction

Hash functions process arbitrarily long input by repeating a compression function f that takes a fixed-size chaining value and a fixed-size message block. If f is collision-resistant, so is the whole hash (Merkle and Damgård, 1989).
MD4, MD5, SHA-1, SHA-2 (SHA-256/512), Whirlpool all use it.
  1. Pad the message (append 1, zeros, then the original length) to a multiple of the block size.
  2. Split into blocks M₁ … Mt.
  3. H₀ = fixed initial value (IV); Hi = f(Hi−1, Mi).
  4. Digest = Ht.
Vulnerable to length-extension attacks (knowing h(M) lets you compute h(M ‖ padding ‖ X)), so h(key ‖ M) is not a safe MAC — use HMAC. SHA-3 uses a different (sponge) design.

Message authentication: MDC, MAC and HMAC

A modification detection code (MDC) is a plain hash — it detects changes but not who made them. A message authentication code (MAC) mixes a shared secret key into the hash, so only key holders can produce a valid tag: integrity + data-origin authentication. HMAC is the standard way to build a MAC from any hash.
HMAC-SHA256 in TLS, IPSec (AH/ESP), JSON Web Tokens, API request signing (AWS), OTP generators (TOTP in Google Authenticator).
HMAC(K, M) = h[ (K⁺ ⊕ opad) ‖ h[ (K⁺ ⊕ ipad) ‖ M ] ] K⁺ = key padded to the block size; ipad = 0x36 repeated, opad = 0x5C repeated. The double hashing defeats length extension.
A MAC uses a shared key, so it cannot provide non-repudiation (either party could have created it) — digital signatures are needed for that (Unit IV).

3.14 The MD family (MD2, MD4, MD5)

MD5 (Message Digest 5)

Designed by Ron Rivest (1991) as a strengthened MD4. Produces a 128-bit digest from 512-bit blocks. Family: MD2 (1989, 8-bit machines, slow), MD4 (1990, fast, 3 rounds, broken quickly), MD5 (4 rounds).
Was everywhere: file checksums, password hashing in old systems, X.509 certificates, TLS. Still OK as a non-security checksum (detecting accidental corruption).
  1. Padding: append a 1-bit and zeros until length ≡ 448 (mod 512); append the original length as 64 bits → multiple of 512.
  2. Buffer: four 32-bit words A, B, C, D initialised to 67452301, EFCDAB89, 98BADCFE, 10325476.
  3. Compression: each 512-bit block (16 words) goes through 4 rounds × 16 steps = 64 steps. Each round uses a different non-linear function: F(B,C,D) = (B ∧ C) ∨ (¬B ∧ D); G = (B ∧ D) ∨ (C ∧ ¬D); H = B ⊕ C ⊕ D; I = C ⊕ (B ∨ ¬D). Each step: A = B + ((A + func(B, C, D) + M[k] + T[i]) ⋘ s), then rotate the roles of A, B, C, D. T[i] = ⌊232 × |sin i|⌋.
  4. Add the result to the chaining buffer; after the last block, A‖B‖C‖D is the 128-bit digest.
MD5("abc") = 900150983cd24fb0d6963f7d28e17f72.
Broken: 128 bits gives only 264 birthday security; Wang et al. (2004) found collisions in hours, now in seconds. 2008: a rogue CA certificate built from MD5 collisions; 2012: the Flame malware forged a Microsoft code-signing certificate. Never use MD5 for security.

3.15 Whirlpool

Whirlpool: a hash built from an AES-like block cipher

Designed by Vincent Rijmen (co-designer of AES) and Paulo Barreto in 2000; adopted by the European NESSIE project and ISO/IEC 10118-3. Produces a 512-bit digest from 512-bit blocks. Its compression function is a dedicated block cipher W used in the Miyaguchi–Preneel scheme.
TrueCrypt/VeraCrypt (key derivation), some file-integrity tools; an alternative to SHA-2 built on well-understood AES principles.

Message preparation: pad with a 1-bit and zeros so that length ≡ 256 (mod 512), then append the length as a 256-bit number.

Miyaguchi–Preneel:   Hi = EHi−1(Mi) ⊕ Hi−1 ⊕ Mi,   H₀ = 0

(the previous hash is used as the key of cipher W, the message block as the plaintext).

The cipher W works on an 8 × 8 byte state (64 bytes = 512 bits) for 10 rounds. Each round has four AES-like steps:

Key expansion: the round keys are produced by running the same round function on the key, using round constants (rows of S-box values) as the "keys".

Slower than SHA-512 on 64-bit CPUs; less widely deployed and supported by libraries. No practical attack on full Whirlpool is known.

3.16 SHA-512

Secure Hash Algorithm 512

Part of the SHA-2 family published by NIST (FIPS 180-2, 2002), designed by the NSA. SHA-1 (160-bit) had weaknesses, so SHA-2 offers 224/256/384/512-bit digests. SHA-512 produces a 512-bit digest using 64-bit words — fast on 64-bit CPUs.
Digital signatures and certificates, Linux password hashing (sha512crypt), Ed25519 signatures, file integrity, HMAC-SHA512, Bitcoin-style key derivation (BIP32).

Merkle–Damgård based (length-extension issue → use HMAC); slower than SHA-256 on 32-bit/embedded hardware.

Step 1 — Message preparation (padding)

Append a single 1 bit, then enough 0 bits, then a 128-bit field holding the original message length, so the total is a multiple of 1024.

|P| = (−|M| − 129) mod 1024    (1 one-bit + |P| zeros + 128 length bits)

(a) M = "abc" = 24 bits → zeros = (−24 − 129) mod 1024 = −153 mod 1024 = 871. Total = 24 + 1 + 871 + 128 = 1024 → one block. Padded block (hex): 61 62 63 80 00 … 00 00 00 … 18 (0x18 = 24).

(b) |M| = 5000 bits → zeros = (−5000 − 129) mod 1024 = −5129 + 6144 = 1015. Total = 5000 + 1 + 1015 + 128 = 6144 = 6 blocks.

Why is padding needed even when the message is already a multiple of 1024? The length field is always added, so an extra block is created — this prevents some collision tricks.

Step 2 — Initial hash values and constants

Eight 64-bit words A…H start at fixed values: the first 64 bits of the fractional parts of the square roots of the first eight primes (2, 3, 5, …, 19). E.g. A = 6A09E667F3BCC908 (from √2). The 80 round constants K₀…K₇₉ come from the fractional parts of the cube roots of the first 80 primes ("nothing-up-my-sleeve" numbers).

Step 3 — Word expansion (message schedule)

Each 1024-bit block gives 16 words W₀…W₁₅; 64 more are generated:

Wt = σ₁(Wt−2) + Wt−7 + σ₀(Wt−15) + Wt−16   (mod 264),   t = 16…79

σ₀(x) = ROTR¹(x) ⊕ ROTR⁸(x) ⊕ SHR⁷(x);   σ₁(x) = ROTR¹⁹(x) ⊕ ROTR⁶¹(x) ⊕ SHR⁶(x). (ROTR = rotate right, SHR = shift right.)

Step 4 — The round function (80 rounds)

After round 79, each of A…H is added (mod 264) to the corresponding hash word from the previous block. After the last block the eight words, concatenated, form the 512-bit digest.

3.17 Unit III review and self-test

  • Modes: ECB (leaks patterns), CBC (chained, IV), CFB (self-sync stream), OFB (output feedback), CTR (counter, parallel).
  • Stream: LFSR (period 2m − 1, linear → weak alone), RC4 (KSA + PRGA, now deprecated).
  • φ(n): φ(p) = p − 1, φ(pq) = (p − 1)(q − 1). Fermat ap−1 ≡ 1; Euler aφ(n) ≡ 1.
  • Primality: trial division, Fermat (fooled by Carmichael), Miller–Rabin (n − 1 = m·2k). Factorisation: trial, Fermat (x² − n = y²), Pollard p − 1.
  • CRT: x = Σ aiMiMi−1 mod M.
  • RSA: n = pq, ed ≡ 1 mod φ(n), C = Pe, P = Cd. Rabin: C = P² mod n, 4 roots. ElGamal: C₁ = e₁r, C₂ = P·e₂r. ECC: point addition, ECDLP, small keys.
  • Hash: preimage, second preimage, collision resistance; birthday 2n/2; MD5 (128, broken), Whirlpool (512, AES-like W), SHA-512 (1024-bit blocks, 80 rounds, padding (−|M| − 129) mod 1024).
