1.0 Starting from zero: the language of security

Nothing in this unit assumes you have studied security before. This section gives you the vocabulary that every later topic uses.

Imagine you send your bank PIN to a friend over WhatsApp, or you log in to your university portal. The message travels through many computers (routers, Wi-Fi access points, servers) that you do not own. Any of them could read it, change it, block it or pretend to be you. Network security is the set of ideas and tools that let us communicate safely over such an untrusted network. Cryptography (Greek kryptos = hidden, graphein = writing) is the science of transforming messages so that only the intended person can understand them and so that tampering is detected.

Kerckhoffs's principle

Proposed by Auguste Kerckhoffs (1883): a cipher must remain secure even if everything about it except the key is public. The algorithm is assumed to be known to the enemy; only the key is secret.
Every modern standard — DES, AES, RSA, SHA — is fully published. Anyone can study and test them, which is exactly why we trust them.
Design the algorithm openly, let experts attack it for years, then keep only the key secret. If a key leaks, you change the key — not the whole system.
It puts all the burden on key management: if the key is weak (short, guessable) or stolen, security is gone no matter how good the algorithm is. "Security through obscurity" (hiding the algorithm) is the opposite approach and is considered bad practice.

1.1 Basic security goals (the CIA triad)

Information is an asset, so it must be protected like any other asset. Security has three basic goals, remembered as CIA: Confidentiality, Integrity and Availability.

Confidentiality

Information must be hidden from unauthorised access. Only the people who are supposed to read the data can read it. It applies both to data stored (data at rest) and data in transit over a network.
Military secrets, bank account details, medical records, exam question papers, passwords, WhatsApp messages (end-to-end encryption).
Achieved mainly by encryption (symmetric: AES; asymmetric: RSA) and by access control (permissions, passwords). Traffic padding can hide even the amount of communication.
Encryption protects content but not always metadata (who talks to whom, when, how much). If keys are stolen, confidentiality is lost. Encryption alone does not stop an attacker from changing or deleting the data.

Integrity

Information must be changed only by authorised entities and through authorised mechanisms. The receiver should be able to detect whether data was altered — accidentally (noise, bugs) or deliberately (an attacker).
A bank transfer of ₹1,000 must not become ₹10,000 on the way; a downloaded software update must be exactly what the vendor published; marks stored in a university database must not be edited by students.
Hash functions and message digests (SHA-256), MAC/HMAC (hash with a secret key), digital signatures, checksums for accidental errors, database access control and audit logs.
Integrity mechanisms detect modification but generally cannot prevent or undo it. A plain hash (without a key) can be recomputed by an attacker after changing the message, so a key or signature is needed against deliberate attacks.

Availability

Information and services must be available to authorised users when they need them. Data that is perfectly secret and unaltered is useless if nobody can reach it.
Online exam portals during result day, ATM networks, hospital systems, railway reservation (IRCTC Tatkal time), cloud services.
Redundancy (backup servers, RAID, data centres in different cities), load balancing, firewalls and DoS-filtering services, rate limiting, regular backups, disaster-recovery plans.
Cryptography helps very little against availability attacks — you cannot "encrypt away" a flood of traffic. Availability measures cost money, and stronger security checks can themselves reduce availability (e.g. too many login checks slow the system).

Many books extend CIA with more goals. You may write them for extra marks in a "security goals" answer, but mention CIA first.

  • Authentication — proving the identity of a user or the origin of a message.
  • Non-repudiation — a sender cannot later deny having sent a message (or a receiver deny receiving it).
  • Accountability — actions can be traced uniquely to an entity (logs, audit trails).

These appear later as security services (Section 1.3).

A 5-mark question "Explain the security goals" is answered best with the triangle diagram, a two-line definition of each goal, one example each, and how it is achieved.

1.2 Types of attacks

An attack is any action that compromises one of the security goals. A threat is a potential for an attack; a vulnerability is a weakness that the attack exploits. Attacks are classified in two ways: by which goal they threaten (Forouzan) and by whether they are passive or active (Stallings / X.800). A third group — cryptanalytic attacks — targets the cipher itself.

A. Attacks threatening confidentiality

Snooping (eavesdropping / interception)

Unauthorised access to or interception of data. The attacker simply reads the message as it passes — the message itself is not altered.
A person on the same public Wi-Fi capturing packets with a tool like Wireshark and reading an unencrypted HTTP login; tapping a phone line.
Defence: encipherment (encryption) makes the captured data unintelligible. Use HTTPS, VPNs, WPA3 Wi-Fi encryption.
Very hard to detect because nothing changes; the defence is prevention, not detection.

Traffic analysis

Even when data is encrypted, the attacker observes patterns: who is sending to whom, how often, at what time, and how large the messages are. From this, useful information can be inferred.
Noticing a sudden burst of messages between two companies before a merger is announced; deducing which website you visit from encrypted packet sizes.
Defence: traffic padding (inserting dummy data so traffic looks uniform), routing control, onion routing (Tor).
Padding wastes bandwidth; metadata leaks are very hard to eliminate completely.

B. Attacks threatening integrity

Modification

After intercepting a message, the attacker changes it (alters, deletes, delays or reorders parts) to benefit themselves.
Changing "Pay ₹500 to Ravi" into "Pay ₹5000 to Eve" in a banking request.
Defence: message digests/MAC, digital signatures — any change makes verification fail.
Detection is possible, but the original message is lost unless retransmitted.

Masquerading (spoofing)

The attacker impersonates somebody else — pretends to be a legitimate user or server.
A phishing website pretending to be your bank; stealing a user's password and logging in as that user; IP or e-mail address spoofing.
Defence: authentication — passwords + OTP, digital certificates (for websites), authentication exchange protocols such as Kerberos.
If credentials are stolen, the system cannot distinguish the attacker from the real user. Multi-factor authentication reduces this.

Replaying

The attacker captures a valid message and sends it again later to produce an unauthorised effect. The message is genuine — only its re-use is malicious.
Capturing an encrypted "transfer ₹2000 to X" request and resending it ten times; replaying a captured car-key-fob signal.
Defence: include a timestamp, sequence number or nonce (number used once) in every message so old copies are rejected.
Timestamps need synchronised clocks; nonces need the receiver to remember previously used values.

Repudiation

Unlike the others, this attack is done by one of the two communicating parties: the sender later denies having sent a message, or the receiver denies having received it.
A customer orders shares, the price falls, and the customer claims "I never placed that order."
Defence: non-repudiation service using digital signatures (only the sender's private key could have produced them) and notarization by a trusted third party.
If the private key is stolen, the true owner can genuinely deny the action; legal frameworks (e.g. IT Act 2000 in India) are also needed.

C. Attacks threatening availability

Denial of Service (DoS) and DDoS

The attacker slows down or totally interrupts a service. Methods: flooding a server with bogus requests so it cannot answer real ones, deleting server responses, or crashing the service. In a Distributed DoS (DDoS) thousands of compromised machines (a botnet) attack together.
Taking down a shopping site during a sale; the 2016 Mirai botnet that used IoT cameras to knock major websites offline.
Defence: firewalls, rate limiting, traffic filtering/scrubbing services, over-provisioned bandwidth, cookies (e.g. SYN cookies; IKE uses cookies against clogging attacks — Unit IV).
Very hard to stop completely because attack traffic can look like legitimate traffic; defence is expensive.

E. Cryptanalytic attacks (attacks on the cipher)

These are classified by how much the attacker (Eve) knows. Remember Kerckhoffs: Eve always knows the algorithm.

AttackWhat Eve hasGoal / example
Ciphertext-onlyOnly some ciphertextFind plaintext/key. Methods: brute force (try every key), statistical/frequency analysis, pattern analysis. Weakest position for Eve, so a cipher must at least resist this.
Known-plaintextSome plaintext–ciphertext pairs she did not chooseUse the pairs to deduce the key, e.g. old messages that were later made public; standard headers like "Dear Sir".
Chosen-plaintextPairs for plaintexts she chooses (temporary access to the encryption machine)Encrypt carefully chosen inputs to expose structure (used in differential cryptanalysis of DES).
Chosen-ciphertextPairs for ciphertexts she chooses (temporary access to the decryption machine)Common against public-key systems such as RSA.

Brute-force (exhaustive key search)

Try every possible key until meaningful plaintext appears. It always works in theory; the question is how long it takes.
Breaking the Caesar cipher (only 25 keys) is instant; DES (256 keys) was broken in 1998 in 56 hours by the EFF "Deep Crack" machine.
On average the attacker must try half the key space. Time ≈ 2k−1 ÷ (keys tested per second).
Defeated by a large key space: AES-128 has 2128 ≈ 3.4 × 1038 keys — even at 1012 keys/s this takes ~1019 years.

1.3 Security services and mechanisms (ITU-T X.800)

The International Telecommunication Union (ITU-T) standard X.800 defines security services (what protection is provided) and security mechanisms (how it is provided). Think of a service as a goal and a mechanism as a tool.

The five security services

1. Data confidentiality

Protects data from disclosure. It can protect a whole message, part of a message (selective-field confidentiality) and even traffic flow (against traffic analysis).
Encrypting a whole e-mail; encrypting only the credit-card field of an order.
Mechanisms: encipherment, traffic padding, routing control.
Does not guarantee the data is unaltered or comes from who it claims.

2. Data integrity

Ensures data received is exactly what was sent — no modification, insertion, deletion or replay. Can be with recovery (the damage is repaired) or without recovery (only detected).
Software downloads with published SHA-256 values; integrity check value in IPSec packets.
Mechanisms: data-integrity mechanism (check value / MAC), digital signature, encipherment.
Usually detects but does not repair; recovery requires retransmission or backups.

3. Authentication

Confirms identity. Peer-entity authentication: in a connection, each side confirms who the other is (at login/connection time). Data-origin authentication: in connectionless communication, confirms the source of each piece of data.
Logging in to a portal (peer entity); verifying that an e-mail really came from your bank (data origin).
Mechanisms: authentication exchange (passwords, challenge–response, Kerberos), digital signatures, encipherment.
Only as strong as the secret used; stolen passwords or private keys defeat it.

4. Non-repudiation

Protects against denial by one of the parties. Proof of origin: the receiver can prove who sent the data. Proof of delivery: the sender can prove the data was received.
Online contracts, stock-trading orders, e-filing of tax returns signed with a Digital Signature Certificate.
Mechanisms: digital signature, data integrity, notarization (a trusted third party records the transaction).
Fails if the private key is compromised; needs legal recognition of digital signatures.

5. Access control

Prevents unauthorised use of resources: decides who may access what and how (read, write, execute).
File permissions in Linux, role-based access in a college ERP (student vs faculty vs admin).
Mechanism: access-control lists, capability lists, passwords, tokens — combined with authentication.
Misconfiguration is common; insiders with legitimate access can still misuse data.

The eight security mechanisms

1.4 Cryptographic methods (techniques)

The mechanisms above are implemented with two techniques: cryptography (making a message unreadable) and steganography (hiding the very existence of the message). Cryptography itself has three branches.

Symmetric-key (secret-key) cryptography

The same secret key is used for encryption and decryption. Alice and Bob must share the key in advance through a secure channel. Also called conventional or private-key encryption. C = EK(P), P = DK(C).
Encrypting files and disks (BitLocker), Wi-Fi traffic (AES in WPA2), the bulk data in HTTPS after the handshake. Examples: Caesar, DES, 3DES, AES, RC4.
Uses substitution and transposition repeated in rounds (Unit II). Very fast — suitable for large data.
Key distribution problem: how do you share the key securely? For n people, every pair needs a key: n(n − 1)2 keys (1000 users → 499,500 keys). It also cannot provide non-repudiation since both parties hold the same key.

Asymmetric-key (public-key) cryptography

Uses a pair of keys: a public key that anyone may know and a private key kept secret by its owner. What one key encrypts, only the other can decrypt. To send a secret to Bob, Alice uses Bob's public key; only Bob's private key can open it.
Exchanging session keys in HTTPS, digital signatures, e-mail security (PGP), SSH login keys. Examples: RSA, ElGamal, ECC, Rabin.
Based on mathematical "one-way trapdoor" problems: factorising large numbers (RSA, Rabin) or the discrete logarithm (ElGamal, ECC) — Unit III.
Hundreds to thousands of times slower than symmetric ciphers, so it is used only for small data (keys, hashes). Needs a way to trust that a public key really belongs to its owner (certificates — Unit IV).

Hashing

A hash function takes a message of any length and produces a fixed-length digest (fingerprint). It uses no key and is one-way: the message cannot be recovered from the digest.
Checking downloads, storing passwords, digital signatures (sign the digest), blockchain. Examples: MD5, SHA-1, SHA-256, SHA-512, Whirlpool.
Message is padded, split into blocks and processed by a compression function in a chain (Unit III).
Provides integrity, not confidentiality. A keyless hash cannot authenticate the sender (the attacker can recompute it) — you need a MAC or signature. Old hashes (MD5, SHA-1) have practical collisions.

Steganography

Greek for "covered writing": hides the existence of the message inside an innocent-looking cover (text, image, audio, video). An observer does not even know a secret is present.
Digital watermarking to prove ownership of images; hiding a message in the least significant bits (LSB) of image pixels; historically invisible ink, or a message tattooed on a shaved head.
Example (image): each pixel colour value is 8 bits; changing the last bit changes the colour by 1/256 — invisible to the eye. Replace the LSBs of many pixels with the bits of the secret message. Example (text): one or two spaces between words to encode 0 or 1.
Once the method is discovered, the message is exposed (no key-based security). Low capacity: a lot of cover is needed for a little data. Compression or resizing of the cover image can destroy the hidden data. Best used together with encryption.

1.5 Integer arithmetic

Almost every cipher works on integers: letters become numbers (A = 0 … Z = 25), bytes are numbers 0–255, and RSA keys are huge integers. So we begin with plain integer arithmetic.

The set of integers ℤ = {…, −3, −2, −1, 0, 1, 2, 3, …} contains all whole numbers, positive, negative and zero — infinitely many.

A binary operation takes two inputs and gives one output. In ℤ the three binary operations are addition, subtraction and multiplication — the result is always an integer. Division is not a binary operation in ℤ because 7 ÷ 2 = 3.5 is not an integer. Instead, division gives two outputs: a quotient and a remainder.

The division algorithm

For any integer a (the dividend) and positive integer n (the divisor), there are unique integers q (quotient) and r (remainder) such that a = q × n + r,   with 0 ≤ r < n The rule 0 ≤ r < n is crucial: the remainder is never negative.
Every "mod" calculation in cryptography is just the remainder r of this division. Converting letters back after a shift (e.g. 25 + 3 = 28 → 28 − 26 = 2 → C) is the division algorithm with n = 26.

Positive a: a = 255, n = 11 → 255 = 23 × 11 + 2, so q = 23, r = 2.

Negative a: a calculator gives −255 = (−23) × 11 + (−2), but r = −2 is not allowed. Fix: decrease q by 1 and add n to r:

−255 = (−24) × 11 + 9  ⇒  q = −24, r = 9

Check: −24 × 11 = −264, and −264 + 9 = −255 ✓.

The divisor must be positive (n > 0); with n = 0 the division is undefined.

Divisibility

If the remainder is zero (a = q × n), we say n divides a, written n | a. If not, we write n ∤ a. E.g. 4 | 32 because 32 = 8 × 4, but 8 ∤ 42.
Divisibility decides whether inverses exist, whether a linear congruence has solutions, and whether a number is prime (no divisors other than 1 and itself).
Properties (learn these — 2-mark question):
  1. If a | 1, then a = ±1.
  2. If a | b and b | a, then a = ±b.
  3. If a | b and b | c, then a | c.  (3 | 15 and 15 | 45 ⇒ 3 | 45)
  4. If a | b and a | c, then a | (m × b + n × c) for any integers m, n.  (3 | 15 and 3 | 9 ⇒ 3 | (2×15 + 4×9) = 66 ✓)
Facts: 1 divides every integer; every integer divides 0; a positive integer with only two divisors (1 and itself) is prime; one with more is composite.
Checking divisibility of very large numbers (hundreds of digits) by all possible divisors is infeasible — which is exactly what makes RSA secure.

Greatest Common Divisor (GCD) and the Euclidean algorithm

The GCD of two positive integers is the largest integer that divides both. gcd(12, 18) = 6. Two numbers are relatively prime (coprime) if gcd(a, b) = 1, e.g. gcd(8, 15) = 1 even though neither is prime.
Checking whether a key is valid (multiplicative/affine cipher keys must be coprime to 26; RSA's e must be coprime to φ(n)); computing inverses; simplifying congruences.

Listing all divisors is slow for big numbers. Euclid (≈300 BC) used two facts:

Fact 1: gcd(a, 0) = a      Fact 2: gcd(a, b) = gcd(b, r), where r = a mod b

So we keep replacing (a, b) by (b, a mod b) until the second number becomes 0. The first number is then the GCD.

r1 ← a ; r2 ← b
while (r2 > 0) {
    q  ← r1 / r2         // integer quotient
    r  ← r1 − q × r2     // remainder
    r1 ← r2 ; r2 ← r
}
gcd(a, b) ← r1

Extended Euclidean algorithm

Given a and b, it finds gcd(a, b) and two integers s and t such that s × a + t × b = gcd(a, b) (This is called Bézout's identity.) When gcd(a, b) = 1 these coefficients give us multiplicative inverses, which every cipher's decryption needs.
Finding the decryption key of the multiplicative/affine/Hill ciphers, the RSA private key d = e−1 mod φ(n), inverses in ElGamal and in the Chinese Remainder Theorem, and solving linear Diophantine equations.

Run Euclid as before, but carry two extra columns s and t. Each new value follows the same rule as r:

r = r1 − q·r2    s = s1 − q·s2    t = t1 − q·t2

Start with s1 = 1, s2 = 0 and t1 = 0, t2 = 1. When r2 becomes 0, the answers are in the first column: gcd = r1, s = s1, t = t1.

r1 ← a; r2 ← b; s1 ← 1; s2 ← 0; t1 ← 0; t2 ← 1
while (r2 > 0) {
   q ← r1 / r2

   s ← s1 − q × s2 ; s1 ← s2 ; s2 ← s

Linear Diophantine equations

An equation ax + by = c where we want integer solutions. Let d = gcd(a, b). If d ∤ c there is no solution; if d | c there are infinitely many.
A direct application of extended Euclid; the same reasoning is reused for linear congruences (Section 1.8).
  1. Divide the equation by d: a₁x + b₁y = c₁ where a₁ = a/d, b₁ = b/d, c₁ = c/d.
  2. Use extended Euclid to solve a₁s + b₁t = 1.
  3. Particular solution: x₀ = (c/d) × s, y₀ = (c/d) × t.
  4. General solution: x = x₀ + k(b/d), y = y₀ − k(a/d), for any integer k.
Applies only to linear equations with integer coefficients.

1.6 Modular arithmetic

In the division algorithm we often care only about the remainder. Arithmetic that keeps only remainders is called modular arithmetic. You already use it: a clock is arithmetic modulo 12 (9 o'clock + 5 hours = 2 o'clock), days of the week are modulo 7.

The modulo operator

a mod n = r    (the remainder when a is divided by n, with 0 ≤ r < n) n is called the modulus and r the residue. Examples: 27 mod 5 = 2, 36 mod 12 = 0, −18 mod 14 = 10, −7 mod 10 = 3.
Keeps results inside a fixed range — 26 letters, 256 byte values, or a key space. The Caesar cipher is C = (P + 3) mod 26.
Rule for negative numbers: keep adding n until the result lies in 0 … n−1. −7 mod 10 → −7 + 10 = 3.
Programming languages differ: in C/Java/JavaScript, -7 % 10 gives −7, not 3! Cryptographic code must correct this with ((a % n) + n) % n.

The set of residues ℤn

The result of "mod n" is always one of ℤn = {0, 1, 2, …, n − 1}. So ℤ2 = {0, 1}, ℤ6 = {0, 1, 2, 3, 4, 5}, ℤ26 = {0 … 25}.
ℤ26 for English letters; ℤ2 for bits (XOR is addition in ℤ2); ℤ256 for bytes; ℤp for large prime p in Diffie–Hellman and ElGamal.
Infinitely many integers map onto just n residues, like wrapping a number line around a clock with n positions (try the demo below).
Information about the quotient is lost; you cannot recover a from a mod n alone.

Congruence and residue classes

Two integers are congruent modulo n if they leave the same remainder: a ≡ b (mod n)  ⇔  n | (a − b) 2 ≡ 12 ≡ 22 ≡ −8 (mod 10). Note "≡" is a relation, while "mod" in "a mod n" is an operator.
A residue class [a] is the set of all integers congruent to a: [2] (mod 5) = {…, −8, −3, 2, 7, 12, …}. There are exactly n classes mod n and we use the smallest non-negative member as the representative.
Lets us replace huge numbers by small equivalents before calculating, which is how 7200 mod 13 can be done by hand.
Congruence behaves like equality: it is reflexive, symmetric and transitive, and you can add or multiply both sides by the same integer.
You cannot always divide both sides: 2 × 3 ≡ 2 × 8 (mod 10) is true (6 ≡ 16) but 3 ≢ 8 (mod 10). Division is only allowed by numbers coprime to n (i.e. multiplying by an inverse).

Operations in ℤn and their properties

Addition, subtraction and multiplication work as usual, followed by reduction mod n. The key properties let us reduce before or after the operation — whichever is easier:
(a + b) mod n = [(a mod n) + (b mod n)] mod n (a − b) mod n = [(a mod n) − (b mod n)] mod n (a × b) mod n = [(a mod n) × (b mod n)] mod n
Example: 10n mod 3 = (10 mod 3)n = 1n = 1. That is why a number's remainder mod 3 equals the remainder of its digit sum (divisibility rule for 3!).
Examples: (14 + 7) mod 15 = 21 mod 15 = 6; (7 − 11) mod 13 = −4 mod 13 = 9; (7 × 10) mod 20 = 70 mod 20 = 10.
(1,723,345 + 2,124,945) mod 11 = (8 + 9) mod 11 = 6, because 1,723,345 mod 11 = 8 and 2,124,945 mod 11 = 9.
There is no "division" operation; instead we multiply by a multiplicative inverse (next card) — which may not exist.

Inverses: additive and multiplicative

Additive inverse: b is the additive inverse of a in ℤn if a + b ≡ 0 (mod n). Every element has one: b = n − a (and 0 is its own). In ℤ10: (0,0) (1,9) (2,8) (3,7) (4,6) (5,5).

Multiplicative inverse: b is the multiplicative inverse of a if a × b ≡ 1 (mod n), written a−1. It exists if and only if gcd(n, a) = 1. In ℤ10 only 1, 3, 7, 9 have inverses: (1,1) (3,7) (9,9).

Additive inverse = decryption key of the additive (shift) cipher: key 3 → decrypt with 23. Multiplicative inverse = decryption key of the multiplicative cipher, the affine cipher, RSA (d = e−1 mod φ(n)), and is needed in Hill, ElGamal and CRT.

Finding a−1 mod n with extended Euclid: run it on (n, a). Because gcd = 1, s·n + t·a = 1, so t·a ≡ 1 (mod n). The inverse is t mod n (the s column is not needed).

No inverse when gcd(a, n) ≠ 1 — e.g. 8 has no inverse mod 26 — so such values can never be used as multiplicative keys. For small n, trial (try b = 1, 2, 3, …) works, but for large n only extended Euclid is practical.

The sets ℤn* and ℤp

ℤn* is the subset of ℤn containing only the numbers that have a multiplicative inverse (i.e. are coprime to n). ℤ10* = {1, 3, 7, 9}; ℤ6* = {1, 5}. Its size is Euler's φ(n) (Unit III).
When the modulus is a prime p, every non-zero element is coprime to p, so ℤp* = {1, 2, …, p − 1} and ℤp behaves like ordinary fractions — every non-zero number can be "divided by".
Use ℤn when we need additive inverses, ℤn* when we need multiplicative inverses. Diffie–Hellman, ElGamal and DSA all work in ℤp* with a large prime p.
To list ℤn*: write 1 … n−1, keep the ones with gcd(·, n) = 1. ℤ13* = {1, 2, …, 12} (13 is prime).
For composite n, ℤn* is missing elements, so not every equation can be solved.

Modular exponentiation — the square-and-multiply method

Public-key cryptography needs ae mod n for huge e (RSA uses e ≈ 22048-size exponents for decryption). Computing ae first and then reducing is impossible — the number would have billions of digits. Instead we reduce after every multiplication and use the binary form of e.
RSA encryption/decryption, Diffie–Hellman, ElGamal, Fermat and Miller–Rabin primality tests, DSA.

Method A (powers of two — easiest by hand): write e as a sum of powers of 2, compute a1, a2, a4, a8, … by repeatedly squaring mod n, then multiply the needed ones.

Method B (left-to-right square-and-multiply): start with y = 1; for each bit of e from the left: y = y² mod n; if the bit is 1, y = y × a mod n.

Only about 2 × (number of bits of e) multiplications are needed — for a 2048-bit exponent that is ≈ 4096 instead of 22048.

Naïve implementations take different time for 0-bits and 1-bits, which leaks the secret exponent (timing attack, Unit III). Real libraries use constant-time versions.

1.7 Matrices

Matrices are used in the Hill cipher (Unit II), in AES's MixColumns operation and for solving several congruences at once. We need only the basics, but done carefully modulo n.

Definitions and types

A matrix of size l × m is a rectangular array of numbers with l rows and m columns; aij is the element in row i, column j.
  • Row matrix (1 × m), column matrix (l × 1), square matrix (l = m).
  • Zero matrix 0: all entries 0. Identity matrix I: square, 1 on the main diagonal, 0 elsewhere.
A 1 × 2 row matrix holds two plaintext letters in the Hill cipher; a 2 × 2 square matrix is its key. AES arranges 16 bytes as a 4 × 4 "state" matrix.
I = 1001     A = 52130−4216 (3 × 3)
Only square matrices can have a determinant or an inverse.

Operations: addition, scalar and matrix multiplication

Addition/subtraction: same size, add element by element. Scalar multiplication: multiply every element by the number. Matrix multiplication A (l × m) × B (m × p) = C (l × p): number of columns of A must equal number of rows of B; cij = (row i of A) · (column j of B).
Hill encryption is C = P × K (mod 26): a row of letters times the key matrix.

Example: [5 2 1] × [[7],[8],[2]] = 5×7 + 2×8 + 1×2 = 35 + 16 + 2 = 53 (1 × 3 times 3 × 1 gives 1 × 1).

Example: [[5,2],[3,1]] × [[1,4],[2,3]] = [[5+4, 20+6],[3+2, 12+3]] = [[9, 26],[5, 15]].

Matrix multiplication is not commutative: in general A × B ≠ B × A. So P × K and K × P give different ciphertexts — you must use the convention of your textbook consistently.

Determinant

A single number computed from a square matrix. A matrix has an inverse only if its determinant is non-zero (in ordinary arithmetic) or invertible mod n (in modular arithmetic).
Checking whether a Hill-cipher key matrix is usable: det(K) must be coprime to 26.

2 × 2: det [[a, b],[c, d]] = ad − bc.

3 × 3 (expand along row 1 with alternating signs + − +):

det A = a11(a22a33 − a23a32) − a12(a21a33 − a23a31) + a13(a21a32 − a22a31)

For A = [[5,2,1],[3,0,−4],[2,1,6]]: 5(0·6 − (−4)·1) − 2(3·6 − (−4)·2) + 1(3·1 − 0·2) = 5(4) − 2(26) + 1(3) = 20 − 52 + 3 = −29.

For large matrices, cofactor expansion is slow (n! terms); row reduction is used in software.

Inverse of a matrix and residue matrices

The multiplicative inverse A−1 satisfies A × A−1 = A−1 × A = I. A residue matrix has all entries in ℤn. A residue matrix A has an inverse in ℤn if and only if det(A) has a multiplicative inverse in ℤn, i.e. gcd(det A, n) = 1.
Hill-cipher decryption: P = C × K−1 (mod 26).

2 × 2 inverse mod n:

abcd−1 = (ad − bc)−1 × d−b−ca   (mod n)
  1. Compute det = ad − bc, reduce mod n.
  2. Check gcd(det, n) = 1; find det−1 mod n (extended Euclid).
  3. Swap a and d, negate b and c (the adjugate).
  4. Multiply every entry by det−1 and reduce mod n.
  5. Verify A × A−1 ≡ I.
Many matrices are not invertible mod 26 (any with even determinant or a determinant divisible by 13), which reduces the usable key space of the Hill cipher.

1.8 Linear congruence

Cryptanalysis often requires solving equations "mod n". A linear congruence is the modular version of a linear equation.

Single-variable linear equations: ax ≡ b (mod n)

Let d = gcd(a, n).
  • If d ∤ b: no solution.
  • If d | b: exactly d solutions in ℤn.
Finding the key of an affine cipher from known plaintext; solving the "x" in modular key equations; it is the building block of CRT.
  1. Compute d = gcd(a, n). If d ∤ b, stop — no solution.
  2. Divide everything by d: a′ = a/d, b′ = b/d, n′ = n/d. Now a′x ≡ b′ (mod n′) and gcd(a′, n′) = 1.
  3. Multiply both sides by a′−1 mod n′: x₀ = b′ × (a′)−1 mod n′.
  4. All solutions: x = x₀ + k × (n/d) for k = 0, 1, …, d − 1.

An equation like ax + c ≡ b is first rewritten as ax ≡ (b − c) (mod n).

You cannot simply "divide by a" unless a is coprime to n — that is the whole reason for step 2.

d = gcd(10, 15) = 5. Does 5 | 2? No → no solution.

  1. d = gcd(14, 18) = 2. 2 | 12 ✓ → there are 2 solutions.
  2. Divide by 2: 7x ≡ 6 (mod 9).
  3. 7−1 mod 9 = 4 (7 × 4 = 28 ≡ 1). x₀ = 6 × 4 = 24 ≡ 6 (mod 9).
  4. Solutions: x = 6 + k × (18/2) = 6 + 9k → x = 6 and x = 15.
  5. Check: 14 × 6 = 84 = 4 × 18 + 12 ✓; 14 × 15 = 210 = 11 × 18 + 12 ✓
  1. Rewrite: 3x ≡ 6 − 4 = 2 (mod 13).
  2. d = gcd(3, 13) = 1 → one solution.
  3. 3−1 mod 13 = 9 (27 ≡ 1). x = 2 × 9 = 18 ≡ 5. Check: 3(5) + 4 = 19 ≡ 6 ✓

Several equations with the same modulus, e.g. two equations in x and y, can be written in matrix form A × X ≡ B (mod n) and solved as X ≡ A−1 × B (mod n).
Breaking the Hill cipher with known plaintext leads to exactly such a system.

1.9 Unit I review and self-test

  • CIA: confidentiality (secrecy), integrity (no unauthorised change), availability (accessible when needed).
  • Attacks: snooping, traffic analysis (passive → C); modification, masquerading, replaying, repudiation (active → I); DoS (active → A).
  • Cryptanalytic attacks: ciphertext-only, known-plaintext, chosen-plaintext, chosen-ciphertext, brute force.
  • X.800: 5 services (confidentiality, integrity, authentication, non-repudiation, access control) and 8 mechanisms.
  • Techniques: cryptography (symmetric, asymmetric, hashing) and steganography.
  • a = qn + r, 0 ≤ r < n. Euclid: gcd(a, b) = gcd(b, a mod b). Extended Euclid gives s·a + t·b = gcd.
  • a−1 mod n exists ⇔ gcd(a, n) = 1. 2×2 inverse = det−1 × adj.
  • ax ≡ b (mod n): d = gcd(a, n); no solution if d ∤ b, else d solutions spaced n/d apart.
