Q3 Hill cipher: encryption, key inverse, decryption and known-plaintext attack 12 marks

Unit II + Unit IHill cipherMatrix inverse mod 26Cryptanalysis

Using the key K = [[5, 8], [17, 3]] and C = P × K (mod 26):
(a) Encrypt "HELP". (b) Find K⁻¹ and decrypt the ciphertext. (c) Show how an attacker who knows the plaintext "HELP" and its ciphertext can recover K.

Encryption = row vector × matrix. Inverse = det⁻¹ × adjugate (mod 26). Attack: arrange known plaintext as a matrix P and ciphertext as C, then K = P⁻¹C.

Show full step-by-step solution

(a) Encryption

HE = (7, 4): (7·5 + 4·17, 7·8 + 4·3) = (103, 68) ≡ (25, 16) → ZQ.
LP = (11, 15): (11·5 + 15·17, 11·8 + 15·3) = (310, 133) ≡ (24, 3) → YD.
Ciphertext ZQYD.

(b) Inverse of K

  1. det K = 5·3 − 8·17 = 15 − 136 = −121 ≡ 9 (mod 26) (−121 + 130).
  2. gcd(9, 26) = 1 → invertible; 9⁻¹ mod 26 = 3 (27 ≡ 1).
  3. Adjugate [[3, −8], [−17, 5]]; × 3 → [[9, −24], [−51, 15]] ≡ [[9, 2], [1, 15]].
  4. Check: K × K⁻¹ = [[5·9 + 8·1, 5·2 + 8·15], [17·9 + 3·1, 17·2 + 3·15]] = [[53, 130], [156, 79]] ≡ [[1, 0], [0, 1]] ✓.

Decrypt ZQ = (25, 16): (25·9 + 16·1, 25·2 + 16·15) = (241, 290) ≡ (7, 4) = HE; YD = (24, 3): (24·9 + 3·1, 24·2 + 3·15) = (219, 93) ≡ (11, 15) = LP → HELP ✓.

(c) Known-plaintext attack

  1. Write plaintext blocks as rows of P and ciphertext blocks as rows of C: P = [[7, 4], [11, 15]], C = [[25, 16], [24, 3]]. Since C = P × K, we get K = P⁻¹ × C.
  2. det P = 7·15 − 4·11 = 61 ≡ 9; 9⁻¹ = 3. P⁻¹ = 3 × [[15, −4], [−11, 7]] = [[45, −12], [−33, 21]] ≡ [[19, 14], [19, 21]].
  3. K = [[19·25 + 14·24, 19·16 + 14·3], [19·25 + 21·24, 19·16 + 21·3]] = [[811, 346], [979, 367]] ≡ [[5, 8], [17, 3]] ✓ — the secret key.

ZQYD; K⁻¹ = [[9, 2], [1, 15]]; the key is fully recovered from one known 4-letter plaintext because the Hill cipher is linear.

Mixing conventions: if your textbook uses column vectors (C = KP), keep that convention throughout. The attack fails only if the chosen plaintext matrix is not invertible mod 26 — the attacker then picks other blocks.

Why the product is stronger

  • Vigenère alone keeps letter positions, so the Kasiski test finds the key length from repeated fragments; transposition destroys those position patterns.

Q10 Diffie–Hellman key exchange and the man-in-the-middle attack (numerical) 10 marks

Unit IV + Unit IIIDiffie–HellmanDiscrete logMITM

Users A and B use Diffie–Hellman with prime q = 353 and primitive root α = 3. A's private key is 97 and B's is 233.
(a) Compute both public keys and the shared secret. (b) An attacker E with private key 13 intercepts the exchange. Show the keys E shares with A and with B. (c) How is this attack prevented?

Public key = α^private mod q. Shared key = (other's public)^own private. For MITM, E replaces both public keys with α^13.

Show full step-by-step solution

(a)

  1. YA = 3⁹⁷ mod 353 = 40. (97 = 1100001₂; by square-and-multiply.)
  2. YB = 3²³³ mod 353 = 248.
  3. A computes K = YB^XA = 248⁹⁷ mod 353 = 160; B computes K = YA^XB = 40²³³ mod 353 = 160. Both equal α^(97·233) mod 353 ✓.
  4. An eavesdropper sees 353, 3, 40 and 248 but must solve the discrete logarithm 3ˣ ≡ 40 (mod 353) to find 97.

(b) Man-in-the-middle

  1. E computes YE = 3¹³ mod 353 = 175 and sends 175 to both A (pretending to be B) and B (pretending to be A).
  2. A computes 175⁹⁷ mod 353 = 204; E computes the same as 40¹³ mod 353 = 204 → key KAE = 204.
  3. B computes 175²³³ mod 353 = 221; E computes 248¹³ mod 353 = 221 → key KBE = 221.
  4. E decrypts A's messages with 204, reads/changes them, re-encrypts with 221 for B. Neither A nor B notices.

(c) Prevention

Authenticate the public values: sign them with long-term private keys and exchange certificates (station-to-station protocol, authenticated DH in TLS and IKE).

YA = 40, YB = 248, K = 160; under attack KAE = 204, KBE = 221.

Show model answer

1. AES overview. Rijndael (Daemen & Rijmen), FIPS 197 (2001). Non-Feistel substitution–permutation network; 128-bit block arranged as a 4 × 4 byte state (column-major); key 128/192/256 bits with 10/12/14 rounds. [Diagram: pre-round AddRoundKey → Nr − 1 rounds of SubBytes, ShiftRows, MixColumns, AddRoundKey → last round without MixColumns.]

  • SubBytes — every byte replaced by the S-box (multiplicative inverse in GF(2⁸) + affine transform); the only non-linear step → confusion.
  • ShiftRows — row r rotated left by r bytes → spreads bytes across columns.
  • MixColumns — each column multiplied by [[02,03,01,01],…] in GF(2⁸) → diffusion inside the column (omitted in the last round).
