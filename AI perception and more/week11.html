11.1 What reinforcement learning is

An agent learns to make good decisions by interacting with an environment and receiving rewards. It learns from consequences, not from labelled answers.
Supervised learning learns from labelled examples ("here is the correct output"). Unsupervised learning finds structure in unlabelled data. Reinforcement learning learns from a reward signal earned by acting ("act, then find out how good it was").
Three distinctive features of RL: (1) no supervisor, only a reward; (2) delayed feedback; (3) your actions decide what data you see next, so the data is not i.i.d.
In the drone autonomy pipeline (perception → decision → control), RL learns the decision block.
  • Agent = the flight-control policy.
  • Environment = airspace, wind, obstacles.
  • State s = pose, velocity, IMU readings, camera image.
  • Action a = thrust and attitude commands.
  • Reward r = +progress, −crash or drift.
  • Policy π = what to do in each situation.

11.2 Reward, return and discounting

Reward hypothesis: every goal can be expressed as maximising the expected cumulative reward. Define the reward well, and the behaviour emerges.
The agent maximises the return, not the next reward: Gt = Rt+1 + γRt+2 + γ²Rt+3 + … = Σk≥0 γk Rt+k+1, with discount factor γ ∈ [0, 1].
γ → 0: myopic (cares only about the immediate reward). γ → 1: far-sighted (weighs the long term). Why discount? The future is uncertain, and discounting keeps the sum finite.

11.3 Markov Decision Processes, policies and value functions

A Markov Decision Process models sequential decision-making where outcomes are partly random and partly controlled by the agent. It is the tuple (S, A, P, R, γ): states, actions, transition dynamics P(s′ | s, a), reward R(s, a) and discount γ.
Markov property: the next state depends only on the current state and action, not on the earlier history.
Policy π is the agent's behaviour, a mapping from states to actions, and it is what RL ultimately learns. A deterministic policy gives a = π(s) ("in this state, always pitch forward 5°"). A stochastic policy gives π(a | s) ("pitch 70%, hover 20%, yaw 10%"). Stochastic policies aid exploration and are central to policy-gradient methods.
Value functions predict expected return:
  • State value Vπ(s) = Eπ[Gt | s] answers "how good is state s under π?"
  • Action value Qπ(s, a) = Eπ[Gt | s, a] answers "how good is action a in s?"
If Q(s, a) is known for all actions, the best action is just argmaxa Q(s, a), so a value function quietly defines a policy. This works only for finite state and action spaces.
Goal: an optimal policy π* that maximises the expected return from every state (Vπ*(s) ≥ Vπ(s) for all s and π). Almost every algorithm cycles through three steps until the policy stops changing, giving π*, V* and Q*:
  • Evaluate: estimate values under the current policy (prediction).
  • Improve: act greedily with respect to those values (control).
  • Repeat.

Bellman equation: value of a state = immediate reward + discounted value of what follows. Vπ(s) = Eπ[Rt+1 + γVπ(St+1) | St = s].
Optimal form: Q*(s, a) = E[Rt+1 + γ·maxa′ Q*(St+1, a′) | s, a]. This recursive self-consistency lets us solve for the values.

11.4 Exploration vs exploitation

Exploration

Try new, untested actions to discover potentially higher rewards. This is essential for mapping unknown environments and avoiding local optima, e.g. flying an unknown corridor that might be a shortcut.

Exploitation

Use the current best-known knowledge to maximise immediate reward, e.g. the safest known path to the destination.

With probability 1 − ε pick argmaxa Q(s, a); otherwise act uniformly at random. Anneal ε down over training. A purely exploring drone crashes often, and a purely exploiting drone never finds the optimal route.
Because the random choice can also land on the greedy action: P(greedy) = 1 − ε + ε/|A| and P(each other action) = ε/|A|. For ε = 0.2 and 4 actions, P(greedy) = 0.8 + 0.05 = 0.85 (assignment Q10).

11.5 Tabular TD learning: Q-learning and SARSA

Store a value for every (state, action) pair in a lookup Q-table and nudge entries after each step. Temporal-difference (TD) learning learns from every single step by bootstrapping: it updates a guess from a slightly better guess. It is model-free: the agent never needs the dynamics P and learns purely from samples.
Q-learning update: Q(s, a) ← Q(s, a) + α·[ r + γ·maxa′ Q(s′, a′) − Q(s, a) ]. Here α is the learning rate (step size), r + γ·max Q(s′, ·) is the TD target, and target − Q(s, a) is the TD error.
SARSA (State, Action, Reward, State′, Action′): Q(s, a) ← Q(s, a) + α·[ r + γ·Q(s′, a′) − Q(s, a) ], where a′ is the action actually taken next.

Tabular Q-learning, step by step. Initialise Q(s, a) ← 0. For each episode, reset the environment, then until the state is terminal:

  • Pick a with ε-greedy from Q(s, ·).
  • Step the environment to get s′ and r.
  • Apply the update.
  • Set s ← s′.

Interact → update → anneal ε → converge. Given enough visits, Q → Q* and greedy(Q) → π*.

11.6 From tables to deep RL

The curse of dimensionality. A real drone does not live on a grid. Position, velocity and thrust are continuous, which means infinitely many states that no table can index. A raw camera feed is high-dimensional, with millions of pixel combinations. We cannot enumerate states; we must generalise across them.
Function approximation: learn Q̂(s, a; θ) or πθ(a | s), with parameters θ replacing the table. Similar states give similar outputs, so generalisation comes for free, and the state can be raw and high-dimensional. Neural networks are the natural choice:
  • They are universal approximators.
  • They learn features from raw input (pixels, point clouds, IMU streams).
  • They scale with data and are differentiable.
RL supplies the objective and the learning signal (reward, TD error); deep nets supply the representation. This enables end-to-end learning from observation to action.
DQN (Deep Q-Network): Q̂(s, a; θ) takes the state (e.g. stacked frames) as input and outputs one Q-value per discrete action. It is trained to match the Bellman target, the same idea as tabular Q-learning but with gradients. Milestone: DeepMind's DQN learned Atari games from pixels at human level (2015).
Naively bootstrapping a network off itself is unstable. Two tricks fix it:
  • Experience replay: store transitions in a buffer and train on random mini-batches. This breaks the correlation between consecutive samples and reuses data, which is possible because the method is off-policy.
  • Target network: a slowly updated copy θ⁻ provides stable targets, which stops the network "chasing its own tail".

  • PPO (Proximal Policy Optimization) is the industry standard. It limits how much the policy can change in one update, giving stable, monotonic improvement that is easy to tune.

11.7 RL in practice: tools, reward design and sim-to-real

The engineering loop.
  • Environment: defines states, actions, reward, reset and step.
  • Agent: the algorithm (PPO, SAC…) plus its network.
  • Train: collect experience, update parameters, repeat.
  • Evaluate: run the frozen policy and inspect the reward curve and behaviour.
Most applied RL is reward design, environment setup and debugging, not the algorithm.
Gymnasium (the successor to OpenAI Gym) is the standard environment API: obs, info = env.reset(); obs, reward, terminated, truncated, info = env.step(action). The observation and action spaces may be discrete or continuous. Other simulators include MuJoCo, Isaac Sim, PufferLib and Brax.
Stable-Baselines3 provides reliable PyTorch PPO, SAC, TD3, DQN and A2C: model = PPO("MlpPolicy", env); model.learn(total_timesteps=100000). To change algorithm, swap PPO → SAC; the env and API stay the same. The demo trains CartPole (discrete, quick to train); try Pendulum for a continuous action space.
Drone specifics:
  • Reward shaping: dense rewards (distance to goal, smoothness, energy) learn faster than sparse ones (+1 at the goal).
  • The reality gap: a policy trained in simulation often fails on hardware because of unmodelled dynamics, latency and noise.
  • Domain randomisation: randomise mass, wind, sensor noise and delays in simulation, forcing a robust policy that transfers zero-shot to real drones.
  • Safety: constrain exploration on real hardware with safe action limits and fallback controllers.
Applications include intelligent path planning in dynamic environments, end-to-end navigation (raw sensors → low-level control), autonomous driving, recommendation systems (long-term engagement) and RLHF for aligning LLMs with human preferences.

11.8 Generative Adversarial Networks

Generative modelling: given data x drawn from Pdata(x), learn to generate new samples xi ∼ Pdata. GAN idea: introduce a latent variable z with a simple prior p(z) (e.g. N(0, I)), sample it and pass it through a generator x = G(z). The result is a sample from the generator distribution PG, and the goal is PG = Pdata. Different z give different outputs, so z is the source of variety.
A discriminator D outputs D(x) = P(x is real). D is trained to tell real images from generated ones; G is trained so that D wrongly classifies its images as real. They are trained jointly as a two-player minimax game, not a single loss being minimised:
minG maxD V(D, G) = Ex∼Pdata[log D(x)] + Ez∼p(z)[log(1 − D(G(z)))]
D wants D(x) = 1 for real data and D(G(z)) = 0 for fakes; G wants D(G(z)) = 1 (the first term does not depend on G). Training uses alternating gradient updates of D and G.

Optimal discriminator (G fixed): maximise ∫ [Pdata(x) log D(x) + PG(x) log(1 − D(x))] dx pointwise. The result is D*(x) = Pdata(x) / (Pdata(x) + PG(x)).
Substituting it in: minG [ DKL(Pdata ‖ (Pdata+PG)/2) + DKL(PG ‖ (Pdata+PG)/2) − log 4 ] = minG 2·DJS(Pdata, PG) − log 4.
Global optimum: PG = Pdata, so JSD = 0, V = −log 4, and D*(x) = ½ everywhere: the discriminator can only guess.

11.9 GAN problems: vanishing gradients, mode collapse, instability

Vanishing gradients. Early in training the generator's samples are poor, so D easily separates them and D(G(z)) ≈ 0. Write D = σ(a). With LG = log(1 − D): ∂LG/∂D = −1/(1 − D) and ∂D/∂a = D(1 − D), so ∂LG/∂a = −D → 0. The generator learns nothing exactly when it is worst.
Fix: train G to minimise −E[log D(G(z))] instead (the non-saturating loss). Its gradient ∂LG/∂a = −(1 − D) ≈ −1 when D ≈ 0.
Mode collapse. For different z the generator produces similar outputs. It fools the discriminator by capturing only a subset (a few modes) of the data. The samples are sharp and realistic but have little diversity, which is why quality alone is not enough to evaluate a GAN.
Minibatch discrimination (Salimans et al., 2016) lets the discriminator examine how similar a sample is to the other samples in its minibatch:
  • Take an intermediate feature f(xi) ∈ ℝA and multiply it by a learned tensor T ∈ ℝA×B×C to get Mi ∈ ℝB×C.
  • For each row b, compute cb(xi, xj) = exp(−‖Mi,b − Mj,b‖L1).
  • Sum over the batch: o(xi)b = Σj cb(xi, xj).
  • Concatenate o(xi) ∈ ℝB with f(xi).
A collapsed batch then looks suspiciously uniform.
Instability. Alternating updates mean each player optimises against a moving target. The game may oscillate instead of converging, and an almost perfect discriminator early on gives the generator vanishing gradients.

11.10 Wasserstein GAN

When the real and generated distributions don't overlap, JSD saturates at log 2, so all such generators are "as good" and there is no useful gradient. The Wasserstein ("earth mover's") distance is the minimum mass displacement needed to transform one distribution into the other. It keeps growing with the distance, e.g. W = |x| for a shift of x.
Kantorovich–Rubinstein duality: W(μ, μ′) = max‖f‖L ≤ 1 EX∼μ[f(X)] − EX∼μ′[f(X)], where ‖f‖L = max |f(x) − f(x′)|/|x − x′| is the Lipschitz seminorm.
WGAN loss: minG max‖D‖L ≤ 1 Ex∼Pdata[D(x)] − Ez[D(G(z))]. The discriminator (now a "critic") outputs a scalar score instead of a probability. The 1-Lipschitz constraint is handled by (1) weight clipping or (2) a gradient penalty (WGAN-GP).

11.11 GAN architectures: DCGAN, Progressive GAN, cGAN, pix2pix, CycleGAN

DCGAN (Radford et al., 2015): scaling GANs with standard CNNs was hard, so these rules gave stable training:
  • Replace pooling with strided convolutions in D and strided transposed convolutions in G.
  • Use BatchNorm in both D and G.
  • Remove fully connected hidden layers.
  • Use ReLU in G except Tanh at the output.
  • Use LeakyReLU in D.
Generated bedrooms after five epochs show some under-fitting (repeated noise textures). Latent-space interpolation αz1 + (1 − α)z2 gives smooth changes, e.g. a room without a window gradually gaining a large window, which shows G learned meaningful structure rather than memorising.
Progressive GAN (Karras et al., 2017) grows G and D progressively from low to high resolution, improving quality, stability and variation.
Conditional GAN (Mirza & Osindero, 2014): both G and D also receive a condition y (a class label, an image…), so generation is controlled. For example, each MNIST row is generated for one chosen digit.
pix2pix (Isola et al., 2017), image-to-image translation such as edges → photo: D classifies real vs generated {edge, photo} tuples, and unlike an unconditional GAN both G and D observe the input edge map. It needs paired data.
CycleGAN (Zhu et al., 2017) handles unpaired image-to-image translation using a cycle-consistency loss (A → B → A should return the input).
