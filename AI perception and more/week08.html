Object Detection: R-CNN Family, YOLO, SSD, RetinaNet & DETR

From "what is in the image" to "what and where": sliding windows and OverFeat, IoU and non-maximum suppression, two-stage detectors (R-CNN → Fast → Faster R-CNN with the RPN), single-stage detectors (YOLO, SSD, RetinaNet), query-based DETR, and what makes aerial imagery hard.

8.1 From classification to detection

Classification: one label per image. Single-object detection: also say where — a CNN with two heads: class scores (softmax loss) and box coordinates (x, y, w, h) (L2 loss against the correct box). The two losses are added: a multi-task loss on a shared feature extractor (the features for "what" overlap with those for "where", and one backbone is cheaper than two).
Multiple objects: each image needs a different number of outputs (1 object → 4 numbers, 3 → 12, …). Naive fix: apply the CNN to many crops and classify each as an object class or background.
Problem: the CNN must run at a huge number of locations, scales and aspect ratios — very expensive — and the same object gets many overlapping boxes.

8.2 Sliding windows and OverFeat

Sliding window (Vaillant, Monrocq & LeCun, 1994)

  1. Build an image pyramid (several scaled copies) for objects of different sizes.
  2. Slide a fixed-size window over every position at each scale.
  3. Stage-1 network: rough object/no-object response map.
  4. Stage-2 network refines the flagged candidates.
  5. Map detections back to original-image coordinates (known position + scale).
  6. Merge overlapping detections.

The CNN + sliding window idea is 30+ years old; by 2013 what changed was data scale, compute and efficient convolutional implementations.

OverFeat (ILSVRC 2013)

  • One ConvNet for classification, localisation and detection; state of the art on ILSVRC 2013 localisation and detection.
  • Multi-scale sliding window implemented inside the ConvNet: FC layers reinterpreted as 1 × 1 convolutions, so all window positions are scanned in a single forward pass — no cropping and re-running.
  • The "window" is the receptive field (fixed size); objects of different sizes are handled by running on 6 resized copies (multi-scale), not by multiple box shapes.
  • Regression head: replaces the classifier layers (FC 4096 → 1024 → 4 box-edge coordinates), trained with an ℓ2 loss on the frozen feature layers 1–5.
  • Boxes are merged greedily (closest pairs averaged) instead of suppressed.

8.3 IoU and non-maximum suppression

IoU(A, B) = area(A ∩ B) / area(A ∪ B) — 1 for identical boxes, 0 for disjoint ones. A detection is a true positive when its IoU with a ground-truth box exceeds a threshold (commonly 0.5).

Non-maximum suppression (NMS)

  1. Sort all boxes by confidence score.
  2. Discard boxes with low scores.
  3. While boxes remain: select the highest-scoring one (keep it) and remove the remaining boxes whose IoU with it exceeds the threshold (e.g. 0.5).
NMS only removes duplicates. A wrong box that overlaps little (the "side mirror" box C, IoU 0.2) survives; two genuinely different objects that overlap heavily may wrongly be merged.

8.5 R-CNN (Girshick et al., 2014)

Generate region proposals with an external algorithm, crop and resize each, classify each with a CNN, and refine with class-specific SVMs and box regressors.
Region proposals: Selective Search — start from an over-segmentation (Felzenszwalb & Huttenlocher) and recursively merge similar regions (colour, texture, brightness/size, fill), giving a hierarchy of ever larger regions; Edge Boxes — proposals from edges (sparse but informative).
Training pipeline (6 stages): (1) ~2000 proposals per image by Selective Search (no training); (2) supervised pre-training of the CNN (AlexNet) on ImageNet; (3) domain-specific fine-tuning — every proposal warped to 227 × 227 regardless of aspect ratio, positive if IoU ≥ 0.5, lower learning rate; (4) freeze the CNN, extract and cache features for every warped proposal; (5) train one binary linear SVM per class on those features; (6) train one linear box regressor per class on proposals with IoU ≥ 0.6.
Box regression (p = proposal, g = ground truth, centre–width–height): targets tx = (gx − px)/pw, ty = (gy − py)/ph, tw = log(gw/pw), th = log(gh/ph) — scale-invariant centre shifts and log-scale size changes; fitted by regularised least squares on the pooled features.
Multi-stage training and extremely slow inference: the CNN runs independently on each of ~2000 proposals, re-processing the same image content thousands of times.

8.6 Fast R-CNN and RoI pooling

Still uses external proposals (Selective Search / Edge Boxes), but runs the CNN once on the whole image and pools the features of each proposal from the shared feature map. No SVMs.
RoI pooling: a type of max pooling that converts the projected region of any size h × w into a fixed H × W grid — divide into sub-windows of about h/H × w/W and max-pool each.
Multi-task loss: L = Lcls(p, u) + λ·[u ≥ 1]·Lbox(tu, v) — softmax classification plus smooth-L1 box loss; the indicator [u ≥ 1] switches the box loss off for background RoIs (u = 0). Smooth L1 = 0.5x² for |x| < 1, |x| − 0.5 otherwise — less sensitive to outliers than L2.
Because RoI pooling keeps CNN, classifier and regressor in one differentiable path, classification gradients update the shared features — so a separately trained SVM adds nothing. In the comparison diagram, the link from features to classifier changes from "Independent" (R-CNN) to "Joint".
RoI pooling quantises: 15 × 15 → 7 × 7 gives sub-windows of 2.14 cells, which are rounded to whole cells → misalignment between pooled features and the true region. RoI Align (Mask R-CNN) uses bilinear interpolation instead.

8.7 Faster R-CNN and the Region Proposal Network

R-CNN and Fast R-CNN depended on an external, hand-crafted proposal algorithm — a bottleneck even after Fast R-CNN shared the convolutions. Faster R-CNN (Ren et al., 2015) replaces it with a small Region Proposal Network working on the CNN's own feature map — fully learnable, faster, tuned to the data.
RPN: e.g. input 3 × 256 × 256 → features 512 × 16 × 16. At each feature-map point imagine k anchor boxes (k = 9: 3 scales × 3 aspect ratios). Predict an objectness score (k × 16 × 16) and box corrections (4k × 16 × 16); sort all k × 16 × 16 boxes by objectness and keep the top ~300 as proposals; the rest is Fast R-CNN.
Anchor labels: positive if IoU > 0.7 with a ground-truth box (or the highest IoU for that box), negative if IoU < 0.3, ignored in between (ambiguous anchors would give contradictory supervision).
4-step alternating training: (1) train the RPN from ImageNet weights; (2) train a separate Fast R-CNN on step-1 proposals; (3) re-initialise the RPN from the detector, freeze the shared conv layers, fine-tune RPN-only layers; (4) keep them frozen, fine-tune Fast R-CNN-only layers. Freezing stops the two heads pulling the shared features in conflicting directions — both end up on one common backbone.

8.8 YOLO, SSD and RetinaNet

YOLO — You Only Look Once (Redmon et al., 2016)

Pre-train a CNN on classification; split the image into an S × S grid; the cell containing an object's centre is responsible for it. Each cell predicts B boxes (x, y, w, h as offsets + a confidence = Pr(object) × IoU(pred, truth)) and one set of C conditional class probabilities Pr(class | object). Output tensor S × S × (5B + C) — 7 × 7 × 30 for S = 7, B = 2, C = 20. Base network like GoogLeNet with 1 × 1 and 3 × 3 convs; two FC layers produce the tensor. Loss: sums of squared errors for localisation and classification, with indicators so class error counts only if an object is in the cell and box error only for the "responsible" predictor.
One class prediction per cell → two objects whose centres fall in the same cell cannot both be detected.
YOLOv2: BatchNorm on all conv layers; fine-tuning at high resolution; anchor priors from k-means clustering of training boxes (distance = 1 − IoU) instead of hand-picked sizes; multi-scale training (new input size every 10 batches); light DarkNet-19 (19 conv + 5 max-pool); direct location prediction bx = σ(tx) + cx, by = σ(ty) + cy, bw = pwetw, bh = pheth ("predict a small correction"). YOLO9000: joint training with ImageNet's top 9000 classes (classification images backpropagate only the classification loss). YOLO-E: text/visual prompts or prompt-free, open-set, detection + segmentation in real time.

SSD — Single Shot MultiBox Detector

VGG-16 base + extra conv feature layers of decreasing size (a pyramid). Each level predicts offsets for its own anchor boxes (normalised to (0, 1)); larger anchors on coarser maps, so each level handles one object scale. At each location k anchors × (c + 4) outputs via 3 × 3 conv filters → kmn(c + 4) filters for an m × n map. Loss L = (Lcls + αLloc)/N: softmax classification + smooth-L1 localisation over matched boxes.

RetinaNet

Focal loss puts more weight on hard examples and down-weights the many easy background examples of a dense detector; a featurized image pyramid (FPN) detects objects at different scales.

8.9 DETR — detection with Transformers

A query-based detector that directly outputs a set of boxes from a Transformer — no anchors, no box-transform regression, no NMS (Carion et al., 2020).
Four parts: (1) CNN backbone (ResNet-50/101) for features; (2) positional encodings (spatial location) + Transformer encoder (multi-head self-attention + FFN); (3) Transformer decoder taking the encoded features and a fixed set of N learned object queries; (4) prediction heads (FFNs): for each query, object/no-object class and its box. Training matches predictions to ground truth by bipartite (Hungarian) matching; loss = classification + box loss.
Object queries are learned, content-independent "slots" — each query must learn its own specialisation from data, rather than having it hand-designed via anchor scales or grid positions.

8.10 Challenges in aerial imagery

  • All-weather perception (automatic target recognition): generalise across weather — e.g. domain generalisation with a metacognitive Mask R-CNN (Chaudhuri, Sikdar & Sundaram, 2025).
  • Oriented bounding boxes: top-down objects at arbitrary angles are poorly fitted by axis-aligned boxes (DOTA benchmark, Ding et al.).
  • Large-scale imagery: huge images with very many, very small instances.
  • Slant-angle views: appearance changes with viewing angle.
  • Few-shot and open-vocabulary detection: some categories have few or no training images — only their names are known.

Adaptation uses (usually unlabelled) target-domain data during training. Generalisation trains only on the source domain and must handle unseen target conditions (brightened, darkened, blurred, snowy images) with zero access to them during training.
