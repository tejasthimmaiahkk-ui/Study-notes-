5.1 Why vision is hard

  • Images are numbers: a matrix of values in [0, 255]; an RGB image of 1080 × 1080 × 3 has about 3.5 million inputs — a fully connected first layer would need millions of weights per neuron.
  • Appearance changes with lighting, scale, viewpoint and occlusion — the same object gives very different numbers.
  • Hand-crafting features is difficult: manual feature extraction needs domain knowledge (window, door, wheel, roof for a house; wheel, headlight for a car; wing, tail, engine for a plane), and domain-independent hand-crafted features are hard to design.
  • Vision tasks can be regression (continuous output) or classification (class label, often with a probability per class).

5.2 Hubel & Wiesel: the visual cortex

Experiments on the primary visual cortex showed that the visual system is built from receptive fields — each neuron responds only to a small region of the visual field.
  • Simple cells respond to oriented bars at a specific retinal position.
  • Complex cells are position-invariant — they respond to the orientation over a range of positions.
  • First layer, V1: neurons activate depending on orientation; the lecture lists spatial invariance and receptive fields here.
  • Second layer, V2: neurons form a hierarchical organisation.
Takeaway for deep learning: the visual cortex is hierarchical and locally connected, and each layer builds more abstract representations — e.g. for faces: edges and dark spots (low level) → eyes, ears, nose (mid level) → facial structure (high level) (Lee et al., 2009). This structure is closely related to modern CNN architectures.

In the Week 5 assignment, the official key accepted "V1 cells are spatially invariant", "There is a hierarchy in V2 cells" and "The proposed structure is closely related to modern CNN architectures". "Stimulus for vertically placed objects is highest" was wrong.

5.3 From neuroscience to CNNs, and why fully connected networks fail

Four key findings → four CNN ingredients

  • Local receptive fields — each neuron sees only a local region.
  • Hierarchical processing — each layer builds more abstract features.
  • Shared weights — the same detector is reused across the whole image.
  • Spatial pooling — tolerance to spatial shifts.

Goal: an architecture that preserves spatial structure and moves away from "everything connected to everything".

Limitations of fully connected networks

  • Parameter explosion — image size makes the input enormous.
  • No spatial awareness — the image is flattened; moving an object creates a completely new input pattern.
  • No weight sharing — the same feature at a different location needs different weights.

5.4 The Neocognitron (Fukushima, 1980)

A self-organising neural network for pattern recognition "unaffected by shift in position" — the first architecture to explicitly implement hierarchical feature extraction, and the direct ancestor of LeNet, AlexNet and modern CNNs.
  • Hierarchical structure — several layers extract increasingly complex, abstract features, like the biological system.
  • Alternating S-cells and C-cells: S-cells (simple) extract local features; C-cells (complex) provide spatial invariance.
  • Learning: unsupervised (competitive learning).
  • Demonstrated that spatial invariance can emerge from a structured hierarchy.
Exam trap: "S-cells give spatial invariance and C-cells extract local features" is the roles swapped.

5.5 Local features and the spatial network

Input: the 2-D array of pixels. Idea: connect a patch of the image to one hidden neuron, then slide the patch across the image to produce a map of the same local feature everywhere (LeCun et al., 1998).
A local feature is a pattern detectable within a small neighbourhood: edge, corner, blob, gradient direction, texture element. Semantic content emerges from local structure (edges → corners → parts such as eyes, nose, mouth).
Compositionality: objects are made of simple local parts in specific spatial relationships, which helps generalisation across domains. Data efficiency: locality and weight sharing are an inductive bias that reduces the need for massive data — so a better understanding of local features means less training data is needed. Complex (global) features built in later layers are more robust to perturbations.
The global structure matters too: spatial relationships between distant local features need non-local reasoning (scene understanding, context, interactions between objects, robustness to cropping, occlusion and clutter).

5.6 The convolution operation

(I ⊗ F)(i, j) = Σm Σn I(i + m, j + n) F(m, n) — I is the image patch at pixel (i, j), F the filter (kernel) that extracts one local feature. The filter's weights are learned.

  • Lecture example: 5 × 5 binary image ⊗ 3 × 3 "X" filter → a 3 × 3 activation map (computed correctly in the demo: [[3, 3, 2], [2, 2, 2], [2, 3, 2]]).
  • Padding: convolution shrinks the image (6 × 6 with 3 × 3 → 4 × 4). Zero-padding keeps the size; pad by the filter's radius — 3 × 3 → 1, 5 × 5 → 2, 7 × 7 → 3 layers of zeros.
  • Stride s: move the filter s pixels at a time — reduces the map size; useful for large (high-resolution or satellite) images.
  • Output size: ⌊(n + 2p − f)/s⌋ + 1 in each dimension. 32 × 32 with 5 × 5, s = 1, p = 0 → 28 × 28; with p = 2 → 32 × 32.
  • Multi-channel input: a filter always spans all input channels (f × f × C) and sums over them → one 2-D map per filter. N × n × n input with F filters of size N × f × f → F × n × n output (with same padding). RGB 64 × 64 × 3 with 16 filters 3 × 3 → filters are 3 × 3 × 3, output 64 × 64 × 16.
  • Convolution is a linear operation with special structure: it can be written as multiplication by a structured (Toeplitz-like) matrix — matrix–matrix multiplication.

5.7 Pooling

Pooling compresses a feature map while keeping the most important information — it reports whether a local feature is present. Max pooling keeps the strongest response; average pooling the overall presence.
Purpose: reduce the dimension, robustness against (small) translations, keep the presence of the feature. A digit shifted by a few pixels gives almost the same pooled output, because pooling summarises activations within a local neighbourhood.
Pooling loses spatial precision (a problem later for segmentation). Max-pooling is nonlinear; average pooling is linear. Pooling has no learnable parameters.

5.9 A one-layer CNN for digit recognition

MNIST: 70,000 handwritten digits, 28 × 28 grey-scale. Challenges: writing styles vary; digits shift, rotate, stretch; similar pairs (1, 7), (4, 9), (5, 6). But there is strong local structure — curves in "3", a horizontal stroke and diagonal in "7", a closed loop in "0".
Input image → conv layer with 4 learnable filters → 4 activation maps → pooling → 4 class scores → cross-entropy loss. Deeper versions: conv → ReLU → pool repeated, then fully connected layers. All filter and FC weights are learned by backpropagation of the cross-entropy loss.
Before CNNsAfter CNNs
Hand-crafted features (SIFT, HOG); domain expertise neededAutomatic, data-driven feature learning
Shallow networks; limited performanceDeep architectures; superior performance
Feature extractor and classifier designed separatelyEnd-to-end training of the whole pipeline
Slow, computationally expensiveGPU acceleration

Key innovations: weight sharing (same filter everywhere — no translation bias), local connectivity (keeps spatial awareness), hierarchical features (simple → complex, layer by layer), end-to-end training. Why it matters: better accuracy on complex visual tasks, more data → better results (unlike fixed features), scalability to many tasks. Modern CNNs trade accuracy against model size and operations (Canziani et al., 2017).

5.10 Data augmentation

Artificially increase the diversity and size of the training set by creating modified versions of existing samples, so the model sees variations it will meet in the real world (e.g. motion blur, lighting and weather for a drone perception model).
Photometric (appearance robustness): contrast, brightness, Gaussian noise, blur, colour jitter, invert, solarize.
Geometric (spatial invariance): rotation, translation, scaling, cropping (random crop, FiveCrop), affine and perspective transforms, flips.
Use geometric when the target domain differs in…Use photometric when it differs in…
camera viewpoint, object orientation, scale, motion dynamics, platform pose — e.g. drone imagery at varying altitude and angle, driving (lane curvature, ego-motion), sports, robot poseillumination, weather, sensor noise, motion blur, sensor modality — e.g. outdoor robotics in changing weather, night/day adaptation, infrared or SAR imaging
An augmentation is valid only if it preserves the label — validity depends on the task's semantics. Rotating a "6" by 180° gives a "9"; vertically flipping some symbols changes their meaning. When a model has high training but low test accuracy, realistic augmentation helps generalisation (it discourages memorising exact training images) — but guarantees nothing.

5.11 Datasets and the PyTorch pipeline

Classification datasets

  • ImageNet — 1000 classes, used for pre-training.
  • CIFAR-10 — 32 × 32 RGB, 10 classes, 60,000 images; CIFAR-100 — 100 fine-grained classes.
  • MNIST, Fashion-MNIST; Caltech-101/256; Food-101; Oxford-IIIT Pets; Stanford Cars (196 classes, ~16,000 images).
  • Aerial: UC Merced Land Use (21 classes, one of the earliest), AID, EuroSAT (Sentinel-2 land cover), PatternNet, MAVOC (automatic target recognition, EO 31 × 31 and SAR 55 × 55 images; NTIRE 2021 PBVS challenge).

Pipeline

  1. Import libraries; Dataset (samples + labels + transforms) and DataLoader (iterates in mini-batches).
  2. Batch size = samples per mini-batch; iteration = one batch; epoch = one full pass over the dataset (iterations per epoch = dataset size / batch size).
  3. Model: subclass nn.Module; e.g. nn.Conv2d(1, 20, 5) = (in_channels 1, out_channels 20, kernel 5); forward: x = F.relu(self.conv1(x)).
  4. Train loop: model.train() → pred → loss_fn(pred, y) → loss.backward() (accumulates gradients) → optimizer.step() (x += −lr·x.grad) → optimizer.zero_grad().
  5. Test loop under torch.no_grad(); save the checkpoint with the lowest validation loss and use it for inference.

5.12 Transfer learning

Reuse a network pre-trained on a large general dataset (e.g. ImageNet) for a new, usually smaller task. Early conv layers learn generic low-level detectors (edges, colours, textures) that transfer across visual tasks; later layers are more task-specific.
Feature extraction: keep the pre-trained layers fixed (frozen), replace and train only the classifier head.
Fine-tuning: also update some or all pre-trained parameters (usually with a small learning rate), starting from the pre-trained weights.
Small dataset similar to the source → feature extraction; larger or more different dataset → fine-tune more layers.
Reduces the amount of task-specific data and training; standard practice for aerial models (ImageNet backbones).
No guarantee of good (let alone perfect) performance — if the domains differ a lot (RGB → SAR/IR, ground → top-down) the transferred features may help little (negative transfer).
